# MiniMax M3 结构特点分析

> 调研对象：**MiniMax M3**（开源，~428B 总参数 / ~23B 激活参数，1M 上下文，原生多模态）
> 资料来源：官方 config.json（本目录 `MiniMaxAI_MiniMax-M3_config.json`）、官方模型卡（`m3_readme.md`）、MSA 技术报告 [arXiv:2606.13392](https://arxiv.org/abs/2606.13392)
> 选择理由：该模型不在课程 model_code 目录的已讲模型（Kimi K3、Qwen3.6、DeepSeek-V3/V4、GLM-5.2）之列，且其核心创新 MSA（MiniMax Sparse Attention）是区别于"线性注意力"（Kimi K3 的 KDA、Qwen3.6 的 Gated DeltaNet）与"Indexer 稀疏注意力"（GLM-5.2 的 IndexShare/DSA、DeepSeek 的 CSA/HCA）之外的第三条长上下文路线——**块级稀疏注意力 + 独立轻量索引分支**。

---

## 一、整体架构一览

| 项目 | 配置值 | 说明 |
|---|---|---|
| 总参数 / 激活参数 | ~428B / ~23B | MoE 稀疏激活 |
| 层数 | 60 层 | 前 3 层 dense，后 57 层 MoE |
| hidden_size | 6144 | |
| 注意力 | GQA，64 Q 头 / 4 KV 头 | head_dim=128 |
| 上下文 | 1M（max_position_embeddings=1048576） | 由 MSA 支撑 |
| 词表 | 200064 | |
| 位置编码 | RoPE，theta=5e6，partial rotary（rotary_dim=64） | 仅旋转一半维度 |
| 激活函数 | SwiGLU-OAI（alpha=1.702, limit=7.0） | OpenAI 版 SwiGLU 变体 |
| 归一化 | RMSNorm + use_gemma_norm（×(1+w) 而非 ×w） + per-head QK Norm | |
| MTP | 7 个 MTP 模块 + 1 层 next-token predict | 投机解码加速 |
| 视觉 | CLIP 式编码器：32 层 / 1280 维 / 16 头 / patch 14，3D RoPE，patch_merge（spatial_merge_size=2） | 原生多模态 |

**层次布局（关键点）**：`moe_layer_freq` 与 `sparse_attention_freq` 完全同步——
- **Layer 0–2**：Dense FFN + 全注意力（稠密、全连接，负责底层感知与对齐）
- **Layer 3–59**：MoE FFN + MSA 稀疏注意力（57 层全部走稀疏路线）

这与 Kimi K3（KDA 线性注意力按周期交替）、GLM-5.2（IndexShare 每 4 层复用 indexer）一样，体现了 2026 年旗舰模型的共同趋势：**不同层承担不同职能，用非均匀布局换取效率**。

## 二、核心创新：MSA（MiniMax Sparse Attention）

### 2.1 动机

全注意力的 O(N²) 复杂度是长上下文的"先天缺陷"。稀疏注意力的通用思路是增加一个**初筛阶段**：先用廉价手段选出值得精细关注的 KV 区域，再对选中区域做标准 softmax attention。MSA 的初筛器（Index Branch）是一个**极轻量的独立注意力分支**。

### 2.2 双分支结构

```
输入 hidden states (N 个 token)
        │
        ├───────────── Index Branch（廉价索引分支）
        │                 · 每个 GQA 组 1 个 index query 头（共 4 组 → 4 个头）
        │                 · 全局共享 1 个 index key 头，维度 sparse_index_dim=128
        │                 · token 级打分 S_ij = q_i·k_j / √128
        │                 · block max-pooling：块内取最大值聚合为块级分数
        │                 · TopK 选出 k=16 个块（每块 Bk=128 token）
        │
        └───────────── Main Branch（主分支，标准 GQA）
                          · 64 Q 头 / 4 KV 头，head_dim=128
                          · 只对 Index Branch 选中的 16 个块做 softmax attention
                          · 注意力预算：16 × 128 = 2048 token（与 N 无关！）
```

### 2.3 关键设计点（来自 config.json 的 `sparse_attention_config`）

| 配置项 | 值 | 含义 |
|---|---|---|
| `sparse_index_dim` | 128 | indexer 的打分维度，与主分支 head_dim 相同但参数量极小（每组仅 2×128×128） |
| `sparse_num_index_heads` | 4 | 与 KV 头数一一对应：每 GQA 组一个 index query 头 |
| `sparse_topk_blocks` | 16 | 每个 query 每组选 16 个块 |
| `sparse_block_size` | 128 | KV 分块大小，top-k 的选择粒度是"块"而非 token |
| `sparse_score_type` | max | 块级分数用块内 token 打分的**最大值**（max-pooling），保证块内任一强相关 token 都能被召回 |
| `sparse_local_block` | 1 | **强制 local block**：query 自身所在的块始终被选中，保证局部连续性 |
| `sparse_init_block` | 0 | 初始 token（BOS 等）所在块不强制选中 |
| `sparse_attention_freq` | 前 3 层 0，后 57 层 1 | 浅层全注意力，深层稀疏 |

### 2.4 为什么这样设计能 work？（训练方法，论文要点）

1. **KL 对齐损失**：indexer 的训练目标是让选块后的稀疏分布尽量接近全注意力分布——用 Main Branch 组内平均注意力分布作为 teacher，对 indexer 输出做 KL 约束。
2. **Gradient Detach**：top-k 选择不可导，索引分数用 stop-gradient 处理，主分支只从被选中的 KV 接收梯度。
3. **Indexer Warmup**：先用全注意力把 indexer 预热到合理状态，再切换到稀疏模式联训，避免冷启动选块混乱。
4. **强制 Local Block**：兜底局部性，防止 indexer 漏掉近距离 token。

### 2.5 复杂度与实测收益

- 复杂度：`F_MSA(N) = H_kv·d_idx·N²（index 打分，d_idx 很小）+ 4·H_q·d_h·N·k·B_k（主分支，只算选中的 k·B_k 个 KV）`
  - 注意：index 打分虽然是 N²，但维度只有 128 且 KV 头只有 4 个，代价远小于主分支的 full attention；主分支成本从 O(N) 降为常数 k·B_k=2048。
- 论文实测（H800）：1M 上下文下注意力 FLOPs 降 **28.4×**，prefill **14.2×** / decode **7.6×** 加速。
- 官方宣称（M3 vs M2）：1M 上下文每 token 计算量为上代 **1/20**，prefill **9×**、decode **15×** 加速。
- 工程侧：算子层采用 **KV 块外层聚合命中 query**（KV outer gather Q）——每块只读一次、访存连续，在 M3 的 64Q/4KV 配比下计算访存比显著优于 Flash-Sparse-Attention / flash-moba（快 4 倍以上）。

## 三、MoE 配置特点

| 配置项 | 值 | 解读 |
|---|---|---|
| `num_local_experts` | 128 | 路由专家数 |
| `num_experts_per_tok` | 4 | top-4 激活 |
| `n_shared_experts` | 1 | 1 个共享专家（`shared_intermediate_size=3072`），所有 token 必过 |
| `intermediate_size` | 3072 | 单个路由专家 FFN 宽度 |
| `dense_intermediate_size` | 12288 | 前 3 层 dense 层的 FFN 宽度（= 4×3072，等效容量对齐） |
| `scoring_func` | sigmoid | 路由打分用 sigmoid（与 DeepSeek-V3 相同），配合 `use_routing_bias=true` 的路由偏置做负载均衡 |
| `routed_scaling_factor` | 2.0 | 路由输出缩放，缓解训练/推理激活差异（DeepSeek-V3 同款 trick） |

与已讲模型对比：
- 规模远小于 Kimi K3（896 专家选 16），走的是"**中等专家数 + top-4 + 共享专家**"的务实路线；
- 路由机制（sigmoid + bias + scaling）与 DeepSeek-V3 系出同源的设计范式。

## 四、其他结构细节

1. **Partial Rotary（部分旋转）**：`rotary_dim=64`，即 head_dim=128 中只有一半维度做 RoPE，另一半不加位置信息——有助于长外推，也是 GPT-NeoX/部分 MLA 系列的做法。
2. **QK Norm（per_head）**：每个头独立做 RMSNorm 再算注意力，配合 `use_gemma_norm`（RMSNorm 权重以 `1+w` 形式初始化，Gemma 风格），提升训练稳定性——这是 1M 上下文 + 大 hidden 下防 logits 爆炸的组合拳。
3. **SwiGLU-OAI**：`hidden_act=swigluoai`，带 `swiglu_alpha=1.702`（类 ReLU² 的近似）和 `swiglu_limit=7.0`（激活值截断），是 OpenAI 提出的 SwiGLU 数值稳定变体。
4. **MTP（Multi-Token Prediction）**：`num_mtp_modules=7` + `num_nextn_predict_layers=1`，与 GLM-5.2 改进 MTP 提升投机解码接受率的趋势一致——MTP 已从训练技巧变成推理加速组件。
5. **原生多模态**：从 Step 0 混合训练。视觉塔是 CLIP 风格（32 层 / 1280 维 / patch 14 / 3D RoPE），经 `patch_merge`（spatial_merge_size=2）压缩 4 倍后投影到 6144 维进语言主干；支持动态分辨率（36 档 grid）与视频（temporal_patch_size=2）。

## 五、与课程已讲模型的横向对比

| 维度 | MiniMax M3（本次调研） | Kimi K3 | Qwen3.6 | DeepSeek-V4 | GLM-5.2 |
|---|---|---|---|---|---|
| 长上下文路线 | **块级稀疏注意力（MSA）** | KDA 线性注意力 | Gated DeltaNet 线性注意力 | CSA+HCA 混合 | IndexShare/DSA 稀疏 |
| 初筛/压缩方式 | 轻量 index 头选 128-token 块 | 固定压缩矩阵 | 递归状态压缩 | NSA 滑窗+选择 | indexer 选 token 块（每 4 层复用） |
| 稀疏粒度 | 块（128 token）×top-16 | 全量线性 | 全量线性 | token/块 | 块 |
| 专家数/激活 | 128 / top-4 + 1 共享 | 896 / top-16 | 256 / top-8+1 | MoE | MoE |
| 层布局 | 前 3 层 dense+全注意力 | 周期性交替 KDA/Gated MLA | 10×(3 DeltaNet + 1 Attn) | CSA/HCA 间隔 | 稀疏层+共享 indexer |
| 1M 上下文收益 | prefill 9×/decode 15× vs M2 | 线性复杂度 | 线性复杂度 | — | indexer FLOPs 降 2.9× |

**一句话总结**：Kimi/Qwen 押注"线性注意力换掉 softmax"，DeepSeek/GLM 押注"token/块级稀疏 + indexer"，而 M3 的 MSA 是**"保留 softmax 质量、用独立轻量索引分支做块级粗筛"的稀疏路线**，其工程亮点是 KV-outer-gather 的访存优化让理论加速真正落地。
