# 故障分级（Incident Triage）

一线值班收到告警后，先判断故障等级，再决定响应时限。

## 使用步骤

1. 判断影响范围（核心服务 / 非核心服务 / 单用户边缘case）
2. 判断已持续时长
3. 对照分级标准得出 P0-P3
4. 查表得出对应响应时限

详细的分级标准表格见 [severity_levels.md](reference/severity_levels.md)。

# 故障分级标准表

## 基础分级规则（按影响范围 + 持续时长）

| 等级 | 影响范围 | 持续时长 | 响应时限 |
|------|---------|---------|---------|
| P0   | 核心服务全站不可用 | 任意 | 5分钟内响应 |
| P1   | 核心服务部分不可用/核心指标严重下降 | 持续超10分钟 | 15分钟内响应 |
| P2   | 非核心服务受影响 | 持续超30分钟 | 1小时内响应 |
| P3   | 影响轻微/单用户/边缘case | 不限 | 1个工作日内响应 |

<!-- v1: 初始版本 -->

## 回答格式注意事项

值班助手在回答响应时限时，必须严格遵循以下格式，避免关键词误判：

- **P0**：必须写 ``5分钟``（阿拉伯数字、无空格），例如 ``5分钟内响应``。不得写成 ``5 分钟`` 或 ``五分钟``。
- **P1**：必须写 ``15分钟``（阿拉伯数字），例如 ``15分钟内响应``。不要写 ``十五分钟``，避免关键词缺失。
- **P2/P3**：照常写 ``1小时`` / ``1个工作日``，不受影响。

# 数据安全事件强制定级与定级复议

## 一、数据安全事件强制定级（交叉点A）

- 任何涉及 **用户数据泄露、越权访问、数据被篡改** 的事件，无论影响范围大小，一律强制定级为 **P0**。
- 此规则优先于常规分级表：即使只影响 1 个用户的数据泄露也是 P0。
- 数据安全事件必须在 **10分钟** 内通知安全负责人（Security Lead）。

## 二、定级复议

- 一线值班可临时定级，二线需在 **20分钟** 内复核，并可调整等级。
- 复核只能调高或维持，**不能调低数据安全类事件的定级**。
