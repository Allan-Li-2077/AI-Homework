# 第十五周作业

## 一、作业要求与完成概述

**作业要求：** 自己实现一个可以下发 SubAgent 的 Agent，并行完成多项工作。

**完成情况：** 已实现「多语言翻译主 Agent + 五个独立语言子 Skill/SubAgent」体系。主 Agent（`multi-lang-translate`）负责解析用户意图、分发任务、汇总结果；五个子 Skill 分别完成英文、日文、法语、韩语、俄语翻译。支持**并行**与**串行**两种执行模式，可通过 API 或配置文件切换。

| 项目 | 说明 |
|------|------|
| 主 Agent / 主 Skill | `multi-lang-translate`（`TranslateMainAgent`） |
| 子 Skill（SubAgent） | `translate-en` / `translate-ja` / `translate-fr` / `translate-ko` / `translate-ru` |
| 并行实现 | `ThreadPoolExecutor` 同时调用多个子 Skill |
| 串行实现 | 按目标语言顺序依次调用子 Skill |
| 开关持久化 | `data/translate_mode.json` + `POST /translate/config` |

## 三、SubAgent（子 Skill）设计

五个语言能力拆成**独立 Skill**，由主翻译 Skill 调用（也可单独 CLI 运行）：

| 子 Skill | 目标语言 | 触发说法示例 |
|----------|----------|--------------|
| `translate-en` | 英文 | 英文 / 英语 / English |
| `translate-ja` | 日文 | 日文 / 日语 / Japanese |
| `translate-fr` | 法语 | 法语 / 法文 / French |
| `translate-ko` | 韩语 | 韩语 / 韩文 / Korean |
| `translate-ru` | 俄语 | 俄语 / 俄文 / Russian |

- 子 Skill 设置了 `disable-model-invocation: true`，避免被普通对话误自动激活；由主 Skill 统一分发。
- 目标语言不在上述五种时，固定回复：**抱歉，不支持翻译该种语言**。

## 四、多语言翻译如何触发

### 4.1 自然语言触发（推荐）

在对话中输入「翻译」意图 + 目标语言 + 中文正文，例如：

```text
翻译成功英文、法语、俄语：
一缕粽香，串联起江南水乡千年民俗。……
```

系统会：

1. 识别翻译意图（「翻译」「译成」等）
2. 将「翻译成功英文」规范为「翻译成英文」类说法
3. 提取目标语言：英文、法语、俄语 → 激活 `translate-en` / `translate-fr` / `translate-ru`
4. 抽出待译中文正文
5. 主 Agent 按当前模式并行或串行调用子 Skill
6. 按统一格式返回结果

### 4.2 显式调用主 Skill

```text
/skill multi-lang-translate
@multi-lang-translate
```

### 4.3 单独调用某一子 Skill（CLI）

```bash
python skills/translate-en/scripts/run.py "你好"
python skills/translate-ko/scripts/run.py "你好"
```

### 4.4 Web / CLI 入口

```bash
# Web
uvicorn src.serve:app --host 0.0.0.0 --port 8000
# 浏览器打开 http://localhost:8000

# CLI
python src/agent.py
```

## 五、并行与串行：原理与切换方法

### 5.1 执行原理

| 模式 | 实现方式 | 特点 |
|------|----------|------|
| **并行** | `ThreadPoolExecutor` 同时提交多个 `invoke_lang_skill` | 多语种同时请求 LLM，墙钟时间更短 |
| **串行** | `for` 循环按语种依次调用 | 一次只跑一个子 Skill，总时长近似各次相加 |

开关优先级：

1. API 运行时设置（`set_parallel_enabled`）
2. 持久化文件 `data/translate_mode.json`
3. 环境变量 `TRANSLATE_PARALLEL`（`1` 并行 / `0` 串行）
4. 默认并行

### 5.2 切换方法

**方法一：HTTP API（推荐，立即生效并写盘）**

```powershell
# 切换为串行
Invoke-RestMethod -Method Post -Uri http://localhost:8000/translate/config `
  -ContentType "application/json" -Body '{"parallel": false}'

# 切换为并行
Invoke-RestMethod -Method Post -Uri http://localhost:8000/translate/config `
  -ContentType "application/json" -Body '{"parallel": true}'

# 查看当前模式
Invoke-RestMethod http://localhost:8000/translate/config
```

**方法二：直接改配置文件**

编辑 `data/translate_mode.json`：

```json
{
  "parallel": true,
  "mode": "parallel"
}
```

或：

```json
{
  "parallel": false,
  "mode": "serial"
}
```

**方法三：环境变量（需重启服务）**

```powershell
$env:TRANSLATE_PARALLEL = "1"   # 并行
$env:TRANSLATE_PARALLEL = "0"   # 串行
```

### 5.3 结果中的模式标识

译文统一格式开头会标明模式，例如：

```text
并行模式
（或）串行模式

英文：
...

法语：
...

俄语：
...

用时 7.693s，Token 2601
```

## 六、实验样例与并行 / 串行对比

### 6.1 测试输入

```text
翻译成功英文、法语、俄语：
一缕粽香，串联起江南水乡千年民俗。一方老字号，沉淀着跨越百年的匠心坚守。

　　盛夏时节，走进位于浙江省嘉兴市秀洲区新城街道兴耀商务广场的一家五芳斋餐饮门店，玻璃展柜里，鲜肉粽、豆沙粽、杂粮粽、锁鲜速食粽整齐陈列，一旁的青团、蛋黄酥等简餐点心琳琅满目。店员娴熟地打包、装袋，有条不紊地接待着往来顾客。

　　这份四季如常的热闹，打破了节令食品固有的“消费魔咒”。长久以来，不少传统节令食品深陷“逢节热销、过季遇冷”的行业困境：一年仅有数日消费爆发，其余时间市场沉寂、品类闲置，难以融入大众日常生活。

　　如何跳出时节桎梏、实现全年化常态化发展，让节令美食从节令限定变为全年常伴，成为摆在老字号面前的时代考题。五芳斋深谙传统美食传承与变革之道，走出了一条守古法、强底蕴，拓产品、扩场景，塑IP、拓全域的升级之路。
```

主 Agent 识别目标语：**英文、法语、俄语**，并下发三个子 Skill：`translate-en`、`translate-fr`、`translate-ru`。

### 6.2 耗时与资源消耗对比

| 执行模式 | 用时 | Token 消耗 | 说明 |
|----------|------|------------|------|
| **并行** | **7.693s** | **2601** | 三个子 Skill 同时请求模型 |
| **串行** | **32.923s** | **4395** | 英 → 法 → 俄依次执行 |

### 6.3 结果分析

1. **墙钟时间：** 并行约 **7.693s**，串行约 **32.923s**，并行明显更快（约 **4.3×**），符合「多项工作并行完成」的作业目标。
2. **Token：** 并行 **2601**，串行 **4395**；串行更高，可能与模型重试、上下文或单次生成差异有关，并行并不必然增加总 Token。
3. **教学结论：** 主 Agent 负责任务编排，SubAgent 负责任务执行；并行适合多路独立、无强依赖的子任务（如多语种翻译）。

## 八、关键实现要点（对应作业「可下发 SubAgent」）

1. **主 Agent 分发**（`TranslateMainAgent._dispatch`）  
   - `parallel=True`：线程池并行 `invoke_lang_skill`  
   - `parallel=False`：顺序调用  

2. **子 Skill 独立性**  
   - 每个语言一个 Skill 包，主 Skill 通过 `skill_invoke.require_sub_skill` 校验存在后再调用。  

3. **结果汇总**  
   - 收集各子 Skill 的译文、耗时、Token，生成统一 `display` 文案返回前端。  

4. **可观测性**  
   - 返回中含 `mode`、`sub_skills_planned`、`sub_skill_runs`，便于核对并行/串行是否真正生效。
