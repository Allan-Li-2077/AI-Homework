# 模型结构与代码特点分析报告

## 1. 报告范围

本报告分析当前目录中的大模型结构代码与配置文件，覆盖以下模型：

- DeepSeek-V3
- DeepSeek-V4-Pro / DeepSeek-V4-Flash
- Qwen3.6-27B
- Qwen3.6-35B-A3B
- GLM-5.2
- Kimi K3

主要参考文件包括：

- `dsv3_model.py`
- `dsv4_model.py`
- `modeling_qwen3_5_moe.py`
- `modeling_glm_moe_dsa.py`
- `kimi_k3_linear_modeling.py`
- `kimi_k3_modeling.py`
- `kimi_k3_vision_processing.py`
- 各模型对应的 `config.json` 与 `readme.md`

## 2. 总体结论

这些模型代码整体体现了大模型结构从传统 Transformer 向高效长上下文架构演进的趋势。核心变化主要集中在四个方向：

1. 使用 MoE 扩大模型总参数量，同时保持每个 token 的激活参数量可控。
2. 使用 MLA、DSA、KDA、Gated DeltaNet、压缩 KV、线性注意力等机制降低长上下文注意力成本。
3. 使用 FP8、FP4、MXFP4 等低精度量化方式降低显存占用并提升推理效率。
4. 将文本模型扩展到图像、视频等多模态输入，形成统一的条件生成模型。

从代码形态看，`dsv3_model.py` 和 `dsv4_model.py` 更像研究型或教学型实现，结构直接、层次清楚，适合学习底层机制。Qwen、GLM 和 Kimi 相关代码更接近 HuggingFace 工程实现，接口完整，支持缓存、生成、Flash Attention、多模态输入和模型加载，但阅读门槛更高。

## 3. 各模型结构分析

### 3.1 DeepSeek-V3

DeepSeek-V3 的核心代码在 `dsv3_model.py` 中。整体结构为：

```text
Transformer
  -> ParallelEmbedding
  -> 多层 Block
       -> RMSNorm
       -> MLA Attention
       -> RMSNorm
       -> Dense MLP 或 MoE
  -> RMSNorm
  -> Parallel LM Head
```

DeepSeek-V3 的主要结构特点如下：

- 使用 Multi-head Latent Attention，简称 MLA。
- Query 和 KV 采用低秩投影，降低 KV cache 的存储成本。
- KV cache 在 `absorb` 模式下缓存压缩后的 latent 表示，而不是完整 K/V。
- FFN 部分采用前几层 dense、后续 MoE 的混合结构。
- MoE 包含 routed experts 和 shared experts。
- Router 支持 top-k expert 选择、group routing、sigmoid/softmax 打分。
- 支持 FP8 权重量化路径，通过 `act_quant`、`weight_dequant`、`fp8_gemm` 等 kernel 调用实现。
- 支持张量并行中的 vocab parallel embedding、column parallel linear 和 row parallel linear。
- 使用 YaRN RoPE 扩展长上下文。

代码特点：

- 类结构简洁，主干清晰。
- 适合理解 MLA、MoE、RoPE、量化 linear 和 tensor parallel 的基础实现。
- 对外部自定义 kernel 有依赖，不能只靠该文件独立运行完整高性能推理。

### 3.2 DeepSeek-V4-Pro / DeepSeek-V4-Flash

DeepSeek-V4 的核心代码在 `dsv4_model.py` 中，是 DeepSeek-V3 的进一步长上下文增强版本。整体结构为：

```text
Transformer
  -> ParallelEmbedding
  -> Hyper-Connection hidden expansion
  -> 多层 Block
       -> HC pre mixing
       -> RMSNorm
       -> Sparse / Compressed Attention
       -> HC post mixing
       -> HC pre mixing
       -> RMSNorm
       -> MoE
       -> HC post mixing
  -> HC Head
  -> LM Head
  -> optional MTP Block
```

DeepSeek-V4 的主要结构特点如下：

- 支持 1M token 级别上下文。
- 注意力不再只依赖完整 KV cache，而是引入压缩 KV 和稀疏检索。
- `Compressor` 用于将历史 KV 按比例压缩。
- `Indexer` 用于为每个 query 选择相关的历史压缩位置。
- `Attention` 同时结合 sliding window 和 compressed top-k KV。
- 当 `compress_ratio` 为 4 时，使用 learned indexer；其他压缩比例可使用规则 top-k。
- 使用 `sparse_attn` kernel 执行稀疏注意力。
- 引入 Hyper-Connections，每层维护多份 hidden state 副本，并通过 Sinkhorn 风格权重混合。
- MoE 专家支持 FP4，其他线性层可走 FP8。
- Router 支持 hash routing 和 score-based routing。
- 支持 MTP Block，用于多 token prediction / speculative decoding。

DeepSeek-V4-Pro 与 Flash 配置差异：

| 项目 | DeepSeek-V4-Pro | DeepSeek-V4-Flash |
|---|---:|---:|
| hidden size | 7168 | 4096 |
| layers | 61 | 43 |
| attention heads | 128 | 64 |
| routed experts | 384 | 256 |
| activated experts per token | 6 | 6 |
| context length | 1,048,576 | 1,048,576 |
| expert dtype | FP4 | FP4 |
| main quantization | FP8 | FP8 |

代码特点：

- 比 V3 明显复杂，重点服务百万级上下文推理。
- 代码中混合了结构逻辑、压缩逻辑、量化逻辑和缓存逻辑。
- 对底层 kernel 依赖更强，例如 `fp4_gemm`、`fp8_gemm`、`sparse_attn`、`hc_split_sinkhorn`。
- 是本目录中最能体现长上下文高效推理优化的模型代码之一。

### 3.3 Qwen3.6-27B 与 Qwen3.6-35B-A3B

Qwen3.6 相关核心代码在 `modeling_qwen3_5_moe.py` 中。配置文件显示有两个版本：

- `Qwen_Qwen3.6-27B_config.json`
- `Qwen_Qwen3.6-35B-A3B_config.json`

Qwen3.6 的文本结构特点是线性注意力和全注意力混排。配置中 `layer_types` 呈现规律：

```text
linear_attention
linear_attention
linear_attention
full_attention
...
```

即大体上每 4 层中有 3 层线性注意力，1 层完整注意力。

Qwen3.6-35B-A3B 的核心结构为：

```text
Qwen3_5MoeForConditionalGeneration
  -> Vision Model
       -> 3D Patch Embedding
       -> Vision Transformer Blocks
       -> Patch Merger
  -> Text Model
       -> 多层 DecoderLayer
            -> Gated DeltaNet 或 Full Attention
            -> Sparse MoE Block
```

文本侧主要特点：

- 使用 `Qwen3_5MoeGatedDeltaNet` 作为线性注意力/token mixer。
- 周期性插入 `Qwen3_5MoeAttention` 全注意力层。
- 全注意力层使用 gated attention output。
- 每层 FFN 是 `Qwen3_5MoeSparseMoeBlock`。
- MoE 使用 top-k router、routed experts 和 shared expert。
- shared expert 还有单独 gate 控制输出强度。
- 使用 MRoPE，支持文本、图像、视频位置编码。

视觉侧主要特点：

- 使用 `Conv3d` 做视频/图像 patch embedding。
- 使用视觉 RoPE 和 learned position embedding。
- 使用 packed variable-length attention 支持不同尺寸视觉输入。
- 最后通过 patch merger 投影到文本 hidden size。

27B 与 35B-A3B 的主要差异：

| 项目 | Qwen3.6-27B | Qwen3.6-35B-A3B |
|---|---:|---:|
| 类型 | Dense / 非 MoE 文本配置 | MoE |
| hidden size | 5120 | 2048 |
| text layers | 64 | 40 |
| attention heads | 24 | 16 |
| experts | 无 | 256 |
| experts per token | 无 | 8 |
| context length | 262,144 | 262,144 |
| vision tower | 有 | 有 |

代码特点：

- 是 HuggingFace 风格的完整模型实现。
- 支持 `PreTrainedModel`、`GenerationMixin`、cache、Flash Attention、SDPA、gradient checkpointing。
- 类和函数很多，但模块边界清楚。
- 适合研究“线性注意力 + 周期全注意力 + MoE + 多模态”的现代模型组合。

### 3.4 GLM-5.2

GLM-5.2 的核心代码在 `modeling_glm_moe_dsa.py` 中，配置文件为 `zai-org_GLM-5.2_config.json`。

整体结构为：

```text
GlmMoeDsaForCausalLM
  -> GlmMoeDsaModel
       -> Embedding
       -> 多层 GlmMoeDsaDecoderLayer
            -> RMSNorm
            -> GlmMoeDsaAttention
                 -> MLA
                 -> DSA Indexer
                 -> Sparse Attention
            -> RMSNorm
            -> Dense MLP 或 MoE
       -> RMSNorm
  -> LM Head
```

GLM-5.2 的主要结构特点：

- 支持 1M token 上下文。
- 注意力基于 DeepSeek-V3 风格 MLA。
- 额外加入 DSA，即 DeepSeek Sparse Attention 风格的 top-k token 选择。
- 使用 `GlmMoeDsaIndexer` 为 query 选择相关历史 token。
- 支持 IndexShare：部分层复用前面 full indexer 层的 top-k indices。
- 配置中的 `indexer_types` 指定每层是 `"full"` 还是 `"shared"`。
- 前 3 层为 dense MLP，后续大多为 sparse MoE。
- MoE router 使用 sigmoid 打分、group top-k、归一化 top-k 权重和 routed scaling。

代码特点：

- 文件头说明该文件由 transformers modular 文件自动生成。
- 工程接口完整，但不建议直接手改该文件。
- 代码中 DSA 逻辑比较突出，尤其是 `prev_topk_indices` 的跨层传递。
- 是学习稀疏注意力和索引复用机制的好样例。

### 3.5 Kimi K3

Kimi K3 的实现分为两部分：

- 文本模型：`kimi_k3_linear_modeling.py`
- 多模态外壳和视觉塔：`kimi_k3_modeling.py`

配置文件为 `moonshotai_Kimi-K3_config.json`。

整体结构为：

```text
KimiK3ForConditionalGeneration
  -> MoonViT3dPretrainedModel
       -> 3D Patch Embedding
       -> MoonViT3dEncoder
       -> Temporal / Spatial Patch Merger
  -> MM Projector
  -> KimiLinearForCausalLM
       -> KimiLinearModel
            -> 多层 KimiDecoderLayer
                 -> KimiDeltaAttention 或 KimiMLAAttention
                 -> KimiSparseMoeBlock 或 Dense MLP
```

文本侧主要特点：

- 93 层 decoder。
- 使用 69 层 KDA 和 24 层 Gated MLA。
- KDA 即 Kimi Delta Attention，属于线性/状态空间风格的注意力变体。
- KDA 内部包含 Q/K/V 短卷积、chunk 模式和 fused recurrent 模式。
- 推理单 token 时可切换到 recurrent state 更新。
- Gated MLA 类似 DeepSeek MLA，并加入 output gate。
- 使用 Attention Residuals，按 block size 聚合和复用注意力残差信息。
- MoE 使用 896 experts，每 token 激活 16 个。
- 使用 Stable LatentMoE，routed expert 前后可有降维和升维投影。
- 支持 shared experts。

多模态侧主要特点：

- 使用 MoonViT3D 处理图片和视频。
- patch embedding 支持时间、高度、宽度三维网格。
- 视觉输出经过 projector 对齐到文本 hidden size。
- `_merge_input_ids_with_image_features` 将视觉 token 替换到文本中的 media placeholder 位置。
- 最终图像、视频和文本被组织为统一 embedding 序列送入语言模型。

量化特点：

- 配置中使用 compressed-tensors。
- 权重格式为 MXFP4 pack quantized。
- 激活可配合 MXFP8。
- 量化配置会忽略部分模块，如 attention、shared experts、lm_head、vision tower 和 projector。

代码特点：

- 是本目录中结构最复杂的模型之一。
- 同时包含线性注意力、MLA、MoE、latent expert、多模态接入和量化配置。
- 文本模型代码偏推理，部分训练路径明确未实现。
- 多模态部分接近 LLaVA 风格，但视觉塔和 projector 更复杂。

## 4. 横向对比

### 4.1 注意力机制对比

| 模型 | 注意力机制 | 长上下文优化方式 |
|---|---|---|
| DeepSeek-V3 | MLA | 低秩 KV cache + YaRN |
| DeepSeek-V4 | Sparse / compressed MLA | sliding window + compressed KV + indexer |
| Qwen3.6 | Gated DeltaNet + full attention | 线性注意力为主，周期全注意力补全 |
| GLM-5.2 | MLA + DSA | top-k 稀疏注意力 + IndexShare |
| Kimi K3 | KDA + Gated MLA | recurrent/chunk KDA + 少量 full/MLA 层 |

### 4.2 MoE 机制对比

| 模型 | experts 数量 | 每 token 激活 | shared experts | 路由特点 |
|---|---:|---:|---|---|
| DeepSeek-V3 | 256 配置级 | 8 | 有 | sigmoid + group routing |
| DeepSeek-V4-Pro | 384 | 6 | 有 | sqrtsoftplus / hash routing |
| DeepSeek-V4-Flash | 256 | 6 | 有 | sqrtsoftplus / hash routing |
| Qwen3.6-35B-A3B | 256 | 8 | 有 | softmax top-k |
| GLM-5.2 | 256 | 8 | 有 | sigmoid + group top-k |
| Kimi K3 | 896 | 16 | 有 | sigmoid + grouped top-k + latent MoE |

|---|---|---|

## 5. 代码实现风格总结

### 5.1 研究型实现

代表文件：

- `dsv3_model.py`
- `dsv4_model.py`

特点：

- 类层次清晰，适合从上到下阅读。
- 自己实现并行 embedding、parallel linear、RMSNorm、RoPE、MoE 和 Transformer 主干。
- 高性能部分依赖外部 kernel。
- 更适合理解结构思想，不是完整 HuggingFace 模型包。

### 5.2 HuggingFace 工程型实现

代表文件：

- `modeling_qwen3_5_moe.py`
- `modeling_glm_moe_dsa.py`
- `kimi_k3_linear_modeling.py`
- `kimi_k3_modeling.py`

特点：

- 继承 `PreTrainedModel` 和 `GenerationMixin`。
- 支持 cache、attention backend、输出格式、模型加载和生成接口。
- 文件更长，兼容逻辑更多。
- 更适合部署、微调和接入生态，但学习时需要抓主干。

## 6. 学习建议

建议按以下顺序阅读代码：

1. 先读 `dsv3_model.py`，理解 MLA、MoE、RMSNorm、RoPE、并行线性层。
2. 再读 `dsv4_model.py`，重点关注 `Compressor`、`Indexer`、`Attention`、`Block` 和 `Transformer`。
3. 阅读 `modeling_glm_moe_dsa.py`，理解 DSA 和 IndexShare 如何在 HuggingFace 架构里实现。
4. 阅读 `modeling_qwen3_5_moe.py`，观察线性注意力和全注意力混排，以及多模态视觉塔接入。
5. 最后阅读 Kimi K3 相关文件，重点关注 KDA、Gated MLA、LatentMoE、AttnRes 和多模态 placeholder 合并逻辑。

## 7. 最终总结

这批模型展示了当前大模型结构演进的几个关键方向：

- 从 dense Transformer 走向 MoE 稀疏激活。
- 从完整注意力走向低秩注意力、线性注意力、压缩注意力和稀疏检索注意力。
- 从短上下文走向 262K 到 1M token 的超长上下文。
- 从 BF16 推理走向 FP8、FP4、MXFP4 等低精度混合推理。
- 从纯文本模型走向原生图像、视频、文本统一建模。

如果把这些模型放在同一条演进线上看，DeepSeek-V3 是 MLA + MoE 的基础样例，DeepSeek-V4 和 GLM-5.2 代表长上下文稀疏注意力路线，Qwen3.6 和 Kimi K3 代表线性注意力、多模态和 agent 场景优化路线。整体来看，它们的共同目标都是在扩大模型能力的同时，尽量控制长上下文推理的显存和计算成本。
