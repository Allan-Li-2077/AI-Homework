# 日志分析技能(Log Analyzer Skill)

## 概述

本技能旨在帮助你分析日志文件。日志文件是记录系统中发生过的事件的文件,在软件工程和运维工作中非常常见。日志文件有许多不同的种类,本技能将介绍如何处理最常见的几种,以便你回答用户关于日志的问题。

日志之所以重要,是因为它能让我们了解系统在一段时间内发生了什么。例如,当网站变慢时,访问日志可以告诉我们哪些 URL 被请求得最多、请求耗时如何。当应用出现故障时,应用日志可以告诉我们发生了哪些错误、发生频率如何。

## 何时使用本技能

在以下情况下,你应该使用本技能:

- 当你收到用户提供的日志文件并被要求分析时
- 当用户想知道日志文件中有多少错误时
- 当用户想在访问日志中找出被请求最多的 URL 时
- 当用户想找出发起请求最多的 IP 地址时
- 当用户想知道错误率或状态码分布时
- 当用户想了解流量随时间的变化情况,例如每分钟请求数
- 当用户在调试问题、需要查看日志时

## 支持的日志格式

以下是几种常用的日志格式。本节逐一介绍它们的样子,以便你能够识别。

### 1. Nginx 访问日志(combined 格式)

nginx 访问日志的 combined 格式是最常见的日志格式之一。每一行形如:

```
127.0.0.1 - - [04/Aug/2026:10:23:45 +0000] "GET /index.html HTTP/1.1" 200 1043 "http://example.com/" "Mozilla/5.0"
```

各字段依次为:客户端 IP 地址、客户端身份标识(通常是短横线)、已认证用户(通常是短横线)、方括号内的时间戳、引号内的请求行(包含 HTTP 方法、路径和协议版本)、状态码、响应体字节数、引号内的来源页(referrer)URL,最后是引号内的用户代理(user agent)。

### 2. Apache Common 日志格式

Apache common 日志格式与 nginx 格式非常相似,但不包含 referrer 和 user agent。每一行形如:

```
127.0.0.1 - frank [10/Oct/2000:13:55:36 -0700] "GET /apache_pb.gif HTTP/1.0" 200 2326
```

### 3. JSON 日志

许多现代应用以 JSON 格式写日志,每一行是一个 JSON 对象。例如:

```json
{"timestamp": "2026-08-04T10:23:45Z", "level": "ERROR", "message": "database connection failed", "service": "api"}
```

字段名因应用而异。时间戳字段可能叫 "timestamp"、"time"、"ts" 或 "@timestamp";级别字段可能叫 "level"、"severity" 或 "loglevel"。在编写分析代码之前,应该先查看几行内容,弄清实际的字段名。

### 4. 纯文本应用日志

许多应用输出形如下面的纯文本日志:

```
2026-08-04 10:23:45 ERROR Something bad happened
2026-08-04 10:23:46 INFO Starting up the server
```

这类日志通常以 ISO 格式时间戳开头,后跟日志级别关键字(DEBUG、INFO、WARN、ERROR 或 FATAL),再跟消息内容。

## 分步工作流程

分析日志文件时,请仔细遵循以下步骤。

### 第 1 步:理解用户想要什么

首先,确保你理解用户的需求。常见的问题包括:有多少错误、最热门的 URL 是什么、最活跃的 IP 地址是什么、错误率是多少、流量随时间变化如何。如果用户的请求含糊不清,可以提问澄清,但通常可以从上下文推断用户的意图。

### 第 2 步:查看日志文件以了解其格式

在编写任何分析代码之前,应该先查看文件的前几行,了解它是什么格式。可以用 Read 工具读取文件的前二三十行。根据所见内容,判断文件属于上述哪种格式。还应检查文件大小,了解它是否能装入内存,还是需要逐行处理。逐行处理总是更安全,尤其是对大文件。

### 第 3 步:编写 Python 脚本来解析日志

现在需要编写一个解析日志文件的 Python 脚本。应将脚本写入文件,然后用 Bash 工具运行。下面是一个完整示例,可以按需改造用于 nginx 访问日志。该脚本逐行读取文件,用正则表达式解析每一行并收集统计信息:

```python
import re
import sys
from collections import Counter
from datetime import datetime

LOG_PATTERN = re.compile(
    r'(?P<ip>\S+) \S+ \S+ \[(?P<ts>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) [^"]*" '
    r'(?P<status>\d{3}) (?P<size>\d+|-)'
)

status_counts = Counter()
path_counts = Counter()
ip_counts = Counter()
minute_counts = Counter()
total = 0
errors = 0

with open(sys.argv[1], encoding="utf-8", errors="replace") as f:
    for line in f:
        m = LOG_PATTERN.match(line)
        if not m:
            errors += 1
            continue
        total += 1
        status = m.group("status")
        status_counts[status] += 1
        path_counts[m.group("path")] += 1
        ip_counts[m.group("ip")] += 1
        # timestamp like 04/Aug/2026:10:23:45 +0000
        ts = m.group("ts")
        minute = ts[:17]  # keeps date and HH:MM
        minute_counts[minute] += 1

print(f"total parsed lines: {total}")
print(f"unparsed lines: {errors}")
print("\nstatus code distribution:")
for status, count in sorted(status_counts.items()):
    print(f"  {status}: {count}")

five_xx = sum(c for s, c in status_counts.items() if s.startswith("5"))
if total:
    print(f"\n5xx error rate: {five_xx / total:.2%}")

print("\ntop 10 paths:")
for path, count in path_counts.most_common(10):
    print(f"  {path}: {count}")

print("\ntop 10 IPs:")
for ip, count in ip_counts.most_common(10):
    print(f"  {ip}: {count}")

print("\nbusiest 5 minutes:")
for minute, count in minute_counts.most_common(5):
    print(f"  {minute}: {count}")
```

你应该根据用户需求调整这个脚本。例如,如果用户只关心错误,可以筛选状态码以 4 或 5 开头的行,或者级别为 ERROR 的行。如果用户关心特定时间段,可以解析完整时间戳并只统计该时间段内的行。如果日志格式不同,则需要相应修改正则表达式。

### 第 4 步:运行脚本

将脚本保存为文件(例如 /tmp/analyze.py),用 Bash 工具运行:

```bash
python3 /tmp/analyze.py /path/to/access.log
```

如果脚本报错,应仔细阅读错误信息,找出原因,修复脚本并重新运行。常见问题包括:正则表达式不匹配(因为日志格式与预期略有不同)、文件过大、非 ASCII 字符导致的编码问题。遇到编码问题时,请确保如上所示以 errors="replace" 方式打开文件。

### 第 5 步:向用户呈现结果

脚本成功运行后,应以清晰易读的方式向用户呈现结果。用表格或列表展示最重要的数字,始终报告脚本输出的确切数值。建议先总结关键发现,例如"该日志包含 120 万条请求,其中 3.4% 返回了 5xx 错误,被请求最多的路径是 /api/search"。还可以指出注意到的任何异常,比如某个时间点错误突然激增。

## 技巧与故障排查

本节包含各种可能有用的技巧。

- 如果日志文件经 gzip 压缩(以 .gz 结尾),可以先用 gunzip 命令解压,也可以在 Python 中用 gzip 模块代替普通 open 函数打开。
- 如果日志文件非常大(数 GB),注意不要全部载入内存。上面展示的逐行处理是安全的,但不要使用 read() 一次性读取整个文件;Counter 对象也要小心,它会随不同值的数量增长。如果路径可能带有大量不同的查询字符串,考虑在计数前去掉查询字符串。
- 如果用户想按某个特定子串过滤,可以在解析前加上类似 `if "search" not in line: continue` 的条件。
- 如果需要比较时间戳,记住 nginx 使用的格式是 04/Aug/2026:10:23:45 +0000,可以用 `datetime.strptime(ts, "%d/%b/%Y:%H:%M:%S %z")` 解析。JSON 日志通常使用 ISO 格式,可以用 `datetime.fromisoformat` 解析。
- URL 中的查询字符串会让热点路径列表变得嘈杂。通常最好按 "?" 切分只保留路径部分,但如果这样做,应告知用户。
- 有些日志的字段顺序不同或包含额外字段。拿不准时,先打印几行样例及其正则匹配分组,确认解析正确后再相信结果。
- 如果只有一小部分行能被成功解析,说明格式判断很可能错了。回到第 2 步重新查看文件。
