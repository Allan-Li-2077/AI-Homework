# AI News Skill (ai_news)

## 📌 简介

`ai_news` 是一个**操作型 Skill**，用于每日生成 AI 前沿资讯简报。它定义了一套完整的
SOP（标准操作流程），告诉 Agent 如何从权威一手信息源获取 AI 行业动态、学术论文和
产品发布信息，经过严格交叉验证后，按用户个人偏好编排成一份高质量的中文摘要简报。

### 覆盖范围

- 🏭 **工业界动态** — OpenAI/Anthropic/DeepMind/Meta/Microsoft/HuggingFace 等
  10 个官方博客的最新发布
- 📄 **学术论文** — arXiv (cs.CL/cs.LG/cs.AI/cs.CV)、OpenReview、顶会 proceedings、
  HuggingFace Daily Papers 等 10 个来源
- 🚀 **产品与开源项目** — Product Hunt AI、GitHub Trending、YC Launch、
  HuggingFace Models 等 5 个来源
- 🎯 **用户专项** — llama.cpp、Unsloth、vLLM、Ollama、LangChain、LlamaIndex
  等与本地推理和 Agent 开发直接相关的源

### 设计目标

解决一个真实痛点：**AI 领域的资讯过载 + 信息质量参差**。每天有大量 AI 新闻，但
大部分来自自媒体/公众号的二次加工、夸大宣传甚至扭曲解读。本 Skill 坚持"一手信源 +
交叉验证 + 可追溯"原则，确保每一条信息都可以追溯到原始出处。

## 🎯 设计理念

### 为什么选择一手源而非聚合器？

AI 资讯生态中，大部分中文 AI 媒体是"编译+再加工"模式：翻译一篇英文报道 → 加上
自己的理解 → 起一个吸引眼球的标题。这个链条每一步都可能引入错误。

一手源的定义：信息的**创造者自己发布的**内容。比如 OpenAI 在 openai.com 发布
GPT-5 公告，那是原始信息。机器之心转载并加上"GPT-5 震撼发布！"的标题，已经经过
了一层加工。

本 Skill 的核心原则：**信息只从创造者那里获取，不从转述者那里获取**。

### 为什么需要交叉验证？

单一消息来源不可靠。即使是知名科技媒体也可能：
- 提前泄露不完整的信息
- 基于单一匿名来源做报道
- 错误理解技术细节

交叉验证协议要求 ≥2 个独立来源确认后才能进入正文。单源消息标注"待确认"或放入
观察列表。

### 为什么需要个性化配置？

AI 领域太广了。每天 arXiv 上就有 300-500 篇新论文，加上各公司博客、产品发布，
资讯量巨大。没有偏好过滤，读者会被淹没。

个性化不意味着"不关注的就不收录"，而是：
- 所有前沿都有覆盖（保证广度）
- 用户重点关注领域优先展示（保证深度）
- 排除纯垃圾信息（营销软文、非AI内容）

## 📡 信息源选择标准

### S/A/B 分级标准

| 评级 | 标准 | 数量 |
|------|------|------|
| **S 级** | 信息直接来自创造者。域名属于官方机构，内容未经中间人转述。 | 17 |
| **A 级** | 可信的发现/过滤层，能帮助在信息洪流中定位高质量内容。内容可追溯到 S 级。 | 7 |
| **B 级** | 声誉良好的第三方平台。用于交叉验证和补充发现。不独立的、不可追溯的不用。 | 3 |

### 为什么排除自媒体？

微信公众号、知乎专栏、CSDN、掘金等平台的核心问题是：
1. **不可追溯**：文章引用了某消息，但不给出原始链接或引用错误
2. **无编辑审核**：作者可以自由发表未经核实的内容
3. **算法驱动**：标题党、情绪化表达被算法放大
4. **商业动机**：软文、推广内容伪装成新闻

### 信息源入选门槛

新信息源要加入 `sources.md`，必须满足：
1. 发布的内容能追溯到一手原始出处
2. 发布频率稳定（非一次性或僵尸源）
3. 内容以事实性进展为主（非观点、评论、教程）
4. 非付费墙完全屏蔽（摘要可读则允许）

## 🚀 使用方式

### 作为 Agent Skill 使用

将本目录放入 Agent 的 skills 路径下，Agent 在需要执行 AI 新闻简报任务时会读取
`SKILL.md` 并按其中的 SOP 逐步执行。

### 手动参考使用

即使没有 Agent 自动执行，也可以把 `SKILL.md` 和 `references/sources.md` 当作
一份"AI 资讯获取方法论"来参考：
- `sources.md`：高质量 AI 信息源的 Yellow Pages
- `user_profile.md`：可复用的个性化偏好模板
- `SKILL.md`：完整的采集→验证→编排方法论

### 目录结构

```
ai_news/
├── SKILL.md                    # 核心操作 SOP（主文件）
├── README.md                   # 本文件（介绍与改进日志）
└── references/
    ├── sources.md              # 权威信源清单（评级+URL+描述）
    └── user_profile.md         # 用户个性化偏好配置
```
