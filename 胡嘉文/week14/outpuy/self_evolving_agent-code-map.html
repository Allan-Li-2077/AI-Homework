self_evolving_agent Python 3.12FastAPISSEOpenAI SDK / DeepSeekVanilla JS

「自进化 Agent」教学 Demo：在虚构电商「云购商城」客服场景下，演示 Skill 如何从对话失败中自动演化。 参考 Anthropic Hermes Agent 的 Skill Nudge 机制与 DSPy GEPA 的离线优化思路，用规则评估（非 LLM-as-judge）保证低成本、可复现、可教学。

项目概览

核心功能：主 Agent 仅凭 skills/*.md 回答客服问题；当某块演示题大量答错时， 后台回顾 Agent（Reviewer）分析失败样本、生成 create/patch 操作让 Skill 库"进化"， 用固定 30 题 probe eval 记录每个进化节点的准确率轨迹，最终对比基线 vs 进化后能力。

项说明
运行方式（Web 教学 UI）cd self_evolving_agent && uvicorn serve:app --host 0.0.0.0 --port 8000 --reload，浏览器打开 http://localhost:8000
运行方式（命令行全流程）python src/demo_runner.py（无 UI 依赖，结果落盘 outputs/evolution_log.json）
必需环境变量DEEPSEEK_API_KEY（默认走 DeepSeek，OpenAI 兼容接口）
依赖仅 openai>=1.0.0 + fastapi + uvicorn（requirements.txt）
一次完整实验8-15 分钟，约 200 次 LLM 调用 ≈ 0.2 元（课堂友好）
⚠️ 教学定位：基线准确率约 22%（Agent 诚实推脱"需要联系人工客服"），进化后 70-90%。 数字上的"进化空间"来自虚构政策——LLM 没有先验，Skill 是唯一知识来源。

调用链路

以 Web UI（serve.py）为主线，CLI（demo_runner.py）是同构的同步版本。

  1. 服务启动：FastAPI lifespan（serve.py:70）初始化 outputs/、备份初始 skills，调用 _init()（:48）创建全局状态 _s（SkillManager / Evaluator / Agent / Reviewer），并把 80 题按每块 10 题切成 8 块。
  2. 基线评估：前端 EventSource 连 /stream/baseline（:189），服务端对 60 题逐一执行 agent.answer() + evaluate_answer()，以 SSE eval_q 事件流式推送，结束后写入 _s["eval_results"]["baseline"]。
  3. 单块演示：前端请求 /stream/block/{N}（:247），块内 10 题逐一 answer + evaluate；答错样本累积进 block_failed_turns（只保留失败）。
  4. 分流（核心）：块跑完若 block_failed_turns 为空 → 发 nudge_skipped，技能不变、不调 Reviewer；非空 → 发 nudge_start，仅把这批失败样本送进 Reviewer。
  5. Nudge 进化：reviewer.review(failed_turns)（结合 policies.md）生成 create/patch 操作 JSON，SkillManager.create()/patch() 落地到 skills/*.md，并自动保存版本快照。
  6. Probe 验证：每个 Nudge 后对固定的 30 题跑一次 probe eval（_probe() :154），记录阶段准确率 → 形成进化轨迹曲线。
  7. 最终评估：/stream/final（:351）对 60 题再评估，前端 addComparisonTable()（index.html:671）渲染基线 vs 最终对比表。
  8. 数据落盘（CLI 版）：EvolutionLog.save()（demo_runner.py:166）把 eval_runs / nudge_events / skill_snapshots / question_comparison 写入 outputs/evolution_log.json。

虚线回环 = 进化反馈：SkillManager 落地后，主 Agent 每次 answer() 都会重新 load_all()，因此进化立即生效。

关键逻辑

1. Skill 自进化闭环（教学核心）

Skill 不是 RAG 文档，而是 可修改的操作 SOP。进化对应三种操作（ARCHITECTURE 3.2 节）：

  • patch 补分支：最常见，给已有 Skill 加缺失的边界条件（如"银卡 VIP 60 天"）
  • create 建新 Skill：某类问题完全无覆盖时新建独立文件（如 digital_goods 数字商品）
  • patch 重写：不改信息量、改提示强度（如"⚠️ 数字商品规则，最高优先级，优先于一切 VIP 特权"），对应 GEPA 的"突变"

闭环：Agent 答错 → failed_turns 累积 → Reviewer 分析 → create/patch → 下次回答立即生效。

2. Agent–Evaluator 契约（关键创新）

规则评估的根本难题是"答得含糊算对算错"。项目用显式契约解决（agent.py:22-33 与 evaluator.py:27）：

  • Agent 侧：能从 Skill 答出 → 给具体完整答案，禁止加"联系人工客服"尾巴；答不出 → 仅回答一句"需要联系人工客服"，不编造。
  • Evaluator 侧：答案含 联系人工 → 判定"Agent 推脱"（一票否决）。

收益：评估器无需庞大的同义词表，三种失败原因互斥清晰，且"答对带尾巴"这类模糊样本从根源消失。

3. 三类互斥失败原因（evaluator.py:58-80）

推脱（含"联系人工"）→ 缺 required 关键词 → 命中 forbidden 关键词

诊断即处方：推脱多 → create 新 Skill；缺词多 → patch 加细节；禁词多 → 已有 Skill 需改提示强度。 失败原因分布直接指导 Reviewer 该做什么。

4. 规则评估的两个关键技巧

  • 数字归一化（_normalize() :30）：用 (?<=\d)[,，](?=\d) 一次性删掉数字间的千位分隔符并小写，避免 4,000 vs 4000 误判。
  • 否定前置检测（_forbidden_hits() :36）：forbidden 关键词前 NEG_WINDOW=4 字窗口内出现 不/无/非/未/没 视为被否定、不算命中。例："不可直接取消"不会误伤 forbidden "直接取消"。

5. SkillManager 三重持久化 + 安全 patch

每次变更自动保存三份（skill_manager.py:118-139）：

  • skills/{name}/SKILL.md — 活动版本，Agent 每次调用前读取
  • outputs/skill_versions/{name}_history.json — 完整历史（内容/时间/原因）
  • outputs/skill_snapshots/{name}_v{N}.md — 每版独立文件，供 UI diff

patch()（:68）采用字符串精确替换第一处而非 diff/LLM-rewrite，防止改动无关内容；_bump_version()（:141）用正则给 frontmatter 的 version: 加 1。

6. Reviewer 最小改动三原则（background_reviewer.py:29-37）

  1. 仅修复观察到的失败：不扩展到"相似但未出现"的场景
  2. 最小改动优先：patch 优于 create；old_text 精确到要改的几行
  3. 按频次只修 1~2 类：留出进化梯度，避免一次改完、后续块没进化空间

设计对比 Hermes：Reviewer 只接收失败样本，不带入对全量对话的"美学感知"，杜绝"全对还触发 Nudge"的乱象（ARCHITECTURE 3.3 节）。

7. SSE + 线程池架构

serve.py 用 StreamingResponse 推送事件流（_evt() :87 把 dict 序列化成 data: ... 帧）。 由于 LLM 调用是同步阻塞的，所有 answer/review 都通过 asyncio.to_thread() 丢进线程池（:208/:270/:301），避免阻塞 FastAPI 事件循环导致前端卡死。

8. 前端实现要点（index.html）

  • handleEvent() :403 按 d.type 分发 SSE 事件到各 onXxx() 处理函数，驱动问题流 / Nudge 卡片 / Skill 面板渲染
  • smartScroll() :885：距底 <48px 才自动跟随滚动，避免覆盖用户手动滚动
  • escHtml() :881 对所有动态文本转义，防 XSS
  • run_id 区分 DOM id：基线题用 q_b{id}、最终题用 q_f{id} 前缀，避免 getElementById 取到基线的节点（USAGE_GUIDE Q5）
  • Skill 面板 loadSkills() :736 轮询 /skills；版本弹窗 showVersionModal() :836 展示历史 diff
