「客服 Agent 自进化」教学 Demo —— 参考 Anthropic Hermes 的 Skill Nudge 与 DSPy GEPA，让客服技能从对话失败中自动演化、并量化每版改进。

项目概览

核心功能：虚构电商客服（云购商城）场景下，Agent 每次回答都基于「当前 Skills」知识库；回答错了就把失败样本送给后台 Reviewer，由它比对完整政策后对 Skill 做最小修改（create/patch），再用 probe eval 量化准确率提升。整个流程可步进回放、可还原重置。

启动方式命令
Web 演示 UI（入口①）cd self_evolving_agent && uvicorn serve:app --host 0.0.0.0 --port 8000 --reload → 浏览器打开 http://localhost:8000
CLI 完整实验（入口②）python src/demo_runner.py
一键规则评估python src/rule_eval_with_review.py

依赖 / 环境变量：requirements.txt 仅 openai>=1.0.0（另有 fastapi / uvicorn）；.env 需 DEEPSEEK_API_KEY（默认模型 deepseek-chat）、DASHSCOPE_API_KEY。

核心闭环示意图

关键逻辑

1. Skill 三重持久化（skill_manager.py:20-26）

活动版 skills/{name}/SKILL.md（每次回答前读取）＋ 完整历史 outputs/skill_versions/{name}_history.json ＋ 每版快照 outputs/skill_snapshots/{name}_v{N}.md。版本号 = 历史条目数，解决 Hermes 遗留问题#1（缺乏进化历史）。

2. patch 的「精确替换」机制（skill_manager.py:68-86, 141-145）

patch 用 字符串精确替换第一处（content.replace(old, new, 1)），而非 diff / LLM 整篇重写——防止意外改动无关内容；每次变更用正则把 frontmatter 的 version 自动 +1。

3. 契约式评估（evaluator.py:58-80）

  • _normalize（:30）：去千位分隔符逗号 + 小写，规避「4,000 / 4000」表述差异。
  • 推脱一票否决（:69）：答案含「联系人工」直接判失败——与 Agent 系统提示「不能答只说推脱」互为契约，行为干净、评估简单。
  • required 关键词必须全部出现；forbidden 关键词经 _forbidden_hits（:36）检查前 4 字内是否有否定前缀（不/无/非/未/没），被否定的不算命中。
  • 零 LLM 成本：ground truth 选取政策专有数字/术语，LLM 在无对应 Skill 时无法猜中，保证评估客观且便宜。

4. 权限分层（agent.py vs background_reviewer.py）

主 Agent 的知识只有 skills/（无政策原文）；Reviewer 拥有完整 policies.md 仅作判定标准（background_reviewer.py:24-44），不与回答 Agent 共用，避免政策外泄导致「编造式回答」。

5. Reviewer 最小修复原则（background_reviewer.py REVIEWER_SYSTEM:29-37）

  • 仅修复观察到的失败，不扩展到「样本里没出现」的场景；
  • 最小改动优先：能 patch 不加新 Skill；patch 的 old_text 只含要改的几行；
  • 聚焦核心：按失败条数排序，只修 1~2 类 —— 刻意留出进化梯度。

6. 状态机与实验数据（serve.py:57-66）

phase：idle → baseline_running/done → block_N_running/done → all_blocks_done → final_running → complete。实验记录（outputs/experiment_result.json）：baseline 14/60 = 23.3% → final 40/60 = 66.7%（+43.4pt）。
