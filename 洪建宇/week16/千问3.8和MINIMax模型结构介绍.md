Qwen3.8 模型架构详解
Qwen3.8 是阿里 Qwen 家族于 2026 年 8 月发布的最新一代模型，包含稠密模型（如 Qwen3.8-27B）和旗舰 MoE 模型（Qwen3.8-2.4T-A95B）两条产品线。
注意力机制：3:1 混合注意力（Gated DeltaNet + Gated Attention）
这是 Qwen3.8 最核心的架构创新，继承自 Qwen3.5。
全模型按固定比例将层分为两类：
Gated DeltaNet（门控线性注意力）：计算复杂度为 O(n)，通过更紧凑的状态表示处理历史信息，大幅降低长序列处理成本。涉及投影、门控和状态更新操作。
Gated Attention（门控标准注意力）：即传统的全注意力机制，复杂度 O(n²)，包含 Q/K/V 投影、RoPE 位置编码、Softmax 和 KV Cache 访问。在需要精确理解局部 token 依赖关系的任务上不可替代。
两组的比例为 3:1——每 4 层中 3 层为 Gated DeltaNet，1 层为 Gated Attention。以 Qwen3.8-27B 为例，64 层分为 16 组，每组 3 层 DeltaNet + 1 层全注意力；旗舰 2.4T 模型则是 92 层分为 23 组，69 层线性注意力 + 23 层全注意力。
此外，注意力模块中使用了 GQA（Grouped Query Attention），多个 Query 头共享同一组 K/V 头，以减少 KV Cache 显存占用并提升推理效率。 Qwen3 系列还引入了 QK-Norm（对 Q 和 K 的每个头单独做 RMSNorm 归一化），以提升训练稳定性。



KV Cache：GQA 压缩 + 线性注意力缓解
KV Cache 是长上下文推理的核心瓶颈，Qwen3.8 通过多重手段应对：
GQA 减少缓存体积：通过让多个 Query 头共享 K/V 头（例如 16 个 Q 头共享 8 个 KV 头），KV Cache 体积直接减半。
线性注意力层无需传统 KV Cache：75% 的 Gated DeltaNet 层使用紧凑的状态表示而非显式存储所有历史 token 的 K/V，从根本上降低了长序列下的显存压力。
周期性全注意力层保证精度：25% 的 Gated Attention 层仍然使用标准 KV Cache，确保关键位置不丢失精确的 token 间依赖关系。
这套混合设计是 Qwen3.8-27B 能做到原生 262K 上下文、并通过 YaRN 扩展至约 100 万 token 的关键。



残差连接：Pre-Norm 架构
Qwen3.8 沿用 Pre-Norm（预归一化） 残差结构。
即先对输入做 RMSNorm 归一化，再送入子层（注意力或 FFN），子层输出与子层输入直接相加形成残差连接。这种设计相比 Post-LN 训练更稳定，梯度传播更顺畅。
值得注意的是，与 Kimi K3 引入的 AttnRes（注意力残差，允许模型重新组合多个历史层的输出）不同，Qwen3.8 目前仍采用较为传统的逐层残差结构——每个子层完成后，只和进入该子层之前的 residual 直接相加。



MoE 路由：512 专家 + Top-10 + 1 共享专家（旗舰 2.4T 模型）
Qwen3.8 的旗舰模型 Qwen3.8-2.4T 采用了 稀疏 MoE（Mixture of Experts） 架构：
总参数量：2.4T（2.4 万亿）
每 token 激活参数：95B（950 亿）
专家总数：512 个
每 token 路由激活：10 个专家
共享专家：1 个（所有 token 都会经过）



FFN 层被拆分为多个独立的"专家"子网络，前面放置一个轻量的路由门控（router/gating）网络，决定当前 token 交给哪 10 个专家处理。总参数决定模型"知道多少"（知识容量），激活参数决定模型"跑起来多贵"（推理成本）。2.4T/95B 的配比本质上是用总参数量换知识容量，用激活参数量控制推理开销。
与 Kimi K3 的 896 个专家 / 16 激活相比，Qwen3.8 每个专家更大，但总激活量稍小（95B vs 103B）。
推理阶段采用 TP（张量并行）+ DP（数据并行）+ EP（专家并行） 的组合策略：Attention 部分依赖 TP 拆分矩阵计算，MoE 部分依靠 EP 将不同专家分布到不同 GPU。
稠密模型（如 27B）则不使用 MoE，每个 token 都经过全部参数计算。



激活函数：SwiGLU / SiLU
Qwen3.8 的 FFN 层使用 SwiGLU（即 SiLU 门控变体）激活函数：
FFN(x) = down_proj( SiLU(gate_proj(x)) * up_proj(x) )
具体实现中，gate_proj 和 up_proj 两个线性层被融合为一个合并的列并行层（MergedColumnParallelLinear），然后通过 SiluAndMul 融合算子在一个 CUDA kernel 中完成 SiLU 激活和逐元素乘法，避免两次独立的计算和内存读写，最后由 down_proj 降维回原始维度。
配置中 hidden_act 字段标记为 "silu"，intermediate_size 通常为 hidden_size 的 3 倍左右（例如 1024 → 3072 → 1024）。



精度：BF16 为主，支持多种量化
Qwen3.8 模型权重以 BF16（Brain Floating Point 16） 精度发布，采用 Safetensors 格式存储。
在推理侧，社区和官方支持多种量化方案以适应不同硬件：
NVFP4：SGLang 通过 NVFP4 优化，在单张 RTX 5090 上 decode speed 超过 200 tokens/s
Q8 / Q4 量化：社区广泛测试各种量化精度对推理质量和速度的影响
KV Cache 量化：支持对 KV Cache 进行量化以进一步降低显存占用（但部分设置在复杂推理任务中可能影响质量）
训练侧的精度细节（如混合精度训练策略）Qwen 团队未完整披露，但 2.4T 规模模型的训练必然依赖大规模混合精度方案。


优化器与训练策略
Qwen 团队尚未像 Kimi K3 技术报告那样系统披露 Qwen3.8 的训练基础设施细节。 但根据已有信息可以确认以下几点：
预训练规模：基于 Qwen3 系列的 36 万亿 token 数据集进行训练，覆盖 119 种语言和方言
三阶段预训练：通用阶段（30T+ token，序列长度 4096）→ 推理增强阶段（5T 高质量 token）→ 长上下文阶段（数百 B token，序列长度 32768）
学习率调度：通过 Scaling Laws 预测每个模型的最优学习率和批大小策略，在推理增强阶段加速学习率衰减
后训练：采用四阶段流程——长 CoT 冷启动 → 推理 RL（使用 GRPO 算法）→ 思维模式融合 SFT → 通用领域 RL
MTP（Multi-Token Prediction）：训练了多步 MTP 能力，一次前向传播可同时预测 3 个候选 token，被接受后可减少自回归串行延迟



上下文：原生 262K，扩展至 ~1M
Qwen3.8 的上下文能力分为两个层级：
原生上下文：262,144 tokens（256K），通过长上下文阶段的专项训练实现
扩展上下文：通过 YaRN（Yet Another RoPE Extension） 技术可扩展至约 1,010,000 tokens（约 100 万）
位置编码使用 RoPE（Rotary Positional Embeddings），基频从 10,000 提升至 1,000,000（通过 ABF 技术），配合 YaRN 和 Dual Chunk Attention（DCA）实现推理时的四倍序列长度扩展。
这一能力的底层支撑正是前文所述的混合注意力架构——75% 的 Gated DeltaNet 层以 O(n) 复杂度处理历史信息，使得在超长上下文下不会因 KV Cache 爆炸而导致显存崩溃。



MiniMax M3 是稀宇科技（MiniMax）于 2026 年 6 月 1 日发布并开源的新一代旗舰模型，定位为原生多模态稀疏 MoE 大模型。
注意力机制：MSA（MiniMax Sparse Attention）——两阶段块级稀疏注意力
MSA 是 M3 最核心的架构创新，也是与上一代 M2（全注意力）最大的分野。它并非线性注意力，而是一种基于 GQA 的块级稀疏选择机制，将注意力计算拆成两个独立阶段：
第一阶段：索引分支（Index Branch）
将 KV 序列按固定大小切分为若干 Block
使用轻量级单头 Key + Block Max Pool 对全局百万级 Token 做粗筛打分
从中选出与当前 Query 最相关的 Top-K 个 KV Block
该分支不参与最终生成，仅输出"该看哪几页"，计算开销可忽略
第二阶段：稀疏分支（Sparse Branch）
仅在索引分支选出的 K 个 Block 上，执行标准 GQA（分组查询注意力）
其余 93% 以上的 KV 对被完全跳过，不加载进显存，也不参与矩阵运算
全程使用原始 KV，不做任何潜空间映射或量化压缩——精度零折损
算子层面，M3 采用以 KV 块为外层来聚合命中 Query 的 "KV outer gather Q" 策略，每块只读一次、访存连续。在 M3 的 head 配比下，计算访存比显著优于主流方法，比开源的 Flash-Sparse-Attention 和 FlashMoBA 快 4 倍以上。
与 DeepSeek NSA 的三路设计（压缩+选择+滑窗）不同，M3 只保留纯选择路径，原因是压缩路径会破坏视觉-文本对齐的几何结构，且在多模态文档测试中跨页表格引用准确率下降 11.3%。


KV Cache：块级稀疏访问 + KV Cache 压缩
M3 的 KV Cache 管理策略与 MSA 架构深度耦合：
块级按需加载：由于 MSA 在索引阶段已锁定 Top-K 个相关 Block，推理时只需将这些被选中 Block 的 KV 加载到计算单元，其余 Block 的 KV Cache 虽存在于显存中但不参与计算，大幅降低了有效访存量。
KV Cache 压缩：MSA 配合 KV Cache 压缩技术，进一步减少长序列下的显存占用。
Memory Parallel：通过分布式 KV Cache 管理策略，将超长上下文的 KV 状态分散到多卡，支撑 1M 上下文下的实际部署。
与 M2 时代的全注意力 KV Cache（每个 token 都需要访问所有历史 KV）相比，MSA 让 KV Cache 的有效利用率大幅提升——在 100 万上下文下，M3 每 token 计算量仅为 M2 的 1/20。


残差连接：Pre-Norm 架构
M3 采用标准的 Pre-Norm（预归一化） 残差结构，共 60 层 Transformer 解码器。
具体结构细节：
每个子层（注意力子层和 MoE 子层）之前先做 RMSNorm 归一化
子层输出与子层输入直接相加形成残差连接
注意力子层内部还使用了 QK-Norm：对 Q 和 K 的每个头单独做可学习的 RMSNorm 归一化，提升训练稳定性
模型最顶部再做一次 RMSNorm，然后经线性输出层映射到词表维度
值得注意的是，M3 的前 3 层是例外——它们使用普通的稠密前馈网络搭配标准 GQA（隐藏层维度高达 12288），从第 4 层起才切换为 MSA + MoE 的组合。


MoE 路由：128 专家 + Top-4 + 1 共享专家
M3 采用稀疏混合专家（MoE） 架构，是"低激活、高智能"设计理念的典型代表：
表格
参数	数值
总参数量	428B（4280 亿）
每 token 激活参数	~23B（230 亿）



激活参数占比	~5.4%
专家总数	128 个
每 token 路由激活	4 个专家
共享专家	1 个（所有 token 都经过）
总层数	60 层
隐藏层维度	6144
路由门控网络为每个 token 计算与 128 个专家的匹配分数，选出 Top-4 专家进行计算，再加上 1 个始终参与的共享专家。其余 123 个专家完全不参与当前 token 的计算。
每个专家内部是一个 SwiGLU 前馈网络：输入分两路，一路经 SiLU 激活做门控，另一路保留数值，两路逐元素相乘。输入维度 6144，中间投影维度 3072。
推理部署采用 TP（张量并行）+ EP（专家并行） 的组合策略，适配 SGLang、vLLM、TensorRT-LLM 等主流框架。
激活函数：SwiGLU（SiLU 门控变体）


M3 的 FFN/专家网络使用 SwiGLU 激活函数，与业界主流选择一致：
Expert(x) = down_proj( SiLU(gate_proj(x)) * up_proj(x) )
gate_proj：将 6144 维输入映射到 3072 维，经 SiLU 激活后作为门控信号
up_proj：将 6144 维输入映射到 3072 维，保留原始数值
两路逐元素相乘后，由 down_proj 升维回 6144 维
归一化统一使用 RMSNorm（Root Mean Square Layer Normalization），位置编码使用 RoPE（旋转位置嵌入），并采用 document-wise RoPE 设计以适配稀疏注意力下的长上下文定位。



精度：BF16 训练，BF16/MXFP8 推理
M3 的精度策略分为训练和推理两个层面：
训练精度
模型权重以 BF16（Brain Floating Point 16） 精度发布
推理精度
BF16：全精度推理，质量无损，但显存开销大（428B × 2 bytes ≈ 856GB）
MXFP8（Microscaling FP8）：MiniMax 同步发布的量化版本，显存约减半至 ~428GB，推理速度提升约 1.8 倍，质量保留约 98%
GPTQ-Int4：社区量化方案，显存约 214GB，推理速度提升约 2.5 倍，质量保留约 95%
MSA 架构的一个重要优势是：全程使用原始 KV，不依赖低精度量化压缩。这与线性注意力方案形成对比——后者在 FP8/FP4 低精度下往往存在稳定性问题，而 MSA 由于基于标准 GQA 计算，天然兼容各种低精度训练和推理。


优化器与训练策略
MiniMax 尚未像部分竞品那样完整披露 M3 的训练优化器细节，但综合公开信息可以拼出以下图景：
预训练
三阶段训练：逐步将上下文长度从短序列扩展到 100 万 token
数据规模：预训练数据 Token 规模推至 100 万亿（100T）量级
原生多模态：从 Step 0 开始进行文本、图像、视频等多模态混合训练，使用大量 Interleaved Data（交错数据）
并行策略：采用先进的计算-通信重叠技术（如 LASP+、可变长度循环注意力、专家张量并行 ETP 等）
后训练
Forge 框架：MiniMax 自研的原生 Agent 强化学习框架，实现训练引擎与推理 Agent 的解耦，通过异步调度和树状结构化样本合并实现约 40 倍训练加速
CISPO 算法：MiniMax 自研的强化学习算法，通过裁剪重要性采样权重（而非 token 更新）来提升 MoE 模型在大规模 RL 训练中的稳定性
过程奖励（Process Reward）：端到端监控生成质量，缓解长上下文场景中的信用分配问题


上下文：原生 1M Token
M3 的上下文能力是其最显著的卖点之一：
原生上下文：1,000,000 tokens（100 万），通过 MSA 稀疏注意力架构原生支持
API 保障窗口：至少 512K tokens 可用
1M 上下文的实现依赖三层协同：
架构层：MSA 将注意力复杂度从 O(n²) 降至接近 O(n)，使百万级序列的计算成为可能
训练层：三阶段预训练逐步将序列长度扩展至 100 万，配合 100T token 的交错多模态数据
推理层：MSA 算子针对 NVIDIA Blackwell（SM100）架构深度优化，在 1M 上下文下实现 prefill 9.7 倍加速、decoding 15.6 倍加速
与上一代 M2（全注意力，19.2 万上下文）相比，M3 的上下文长度提升了约 5 倍，而单 token 计算量反而降至 M2 的 1/20。
