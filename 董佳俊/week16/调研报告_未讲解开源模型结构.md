## 1. Meta Muse Glimmer 30B：滑窗 + 全量混合的"端侧 dense"路线

**一句话定位**：Meta 时隔 16 个月重返开源权重，把"滑窗 + 全量注意力"的混合布局做成了 **30B 纯 dense 多模态本地 Agent 模型**，架构朴素但 KV cache 效率极高。

### 1.1 基本信息

| 项 | 值 |
|---|---|
| 厂商 / 许可证 | Meta Superintelligence Labs / Apache 2.0 |
| 规模 | ~29.6B **dense**（语言部分 28B + 感知编码器 ~1.8B），**无 MoE** |
| 上下文 | 131,072+（课程同期 Qwen3.6 原生 256K，这里偏短） |
| 模态 | 输入文本+图像（含视频帧），输出文本 |
| 蒸馏基座 | Muse Spark（仅 API 的闭源旗舰） |

### 1.2 结构拆解（沿五轴线）

**① 注意力：SWA×3 + 全量×1，GQA 16:1**。52 层按 `[局部, 局部, 局部, 全局]` 循环 13 次；滑窗 2048；32 个 Q 头 / 仅 2 个 KV 头。课程讲 DS-V4 时提过"滑窗层保局部细节"，Muse Glimmer 相当于把 CSA/HCA 压缩全部去掉、只留滑窗+全量的极简版：

```jsonc
// config.json: 每 4 层一组，第 4 层全量注意力
"layer_types": ["sliding_attention","sliding_attention","sliding_attention","full_attention", ...],
"sliding_window": 2048,
"num_attention_heads": 32, "num_key_value_heads": 2   // GQA 16:1
```

【社区分析】Raschka 测算其 BF16 KV cache 仅约 **52 KiB/token**（Qwen3.6-27B 64 KiB、Gemma4-31B 840 KiB）——2 个 KV 头 + 滑窗是省 KV 的粗暴但有效组合。

**② 位置编码：局部层 RoPE，全局层 NoPE**。这是本模型最值得注意的细节：`layer_rope_theta` 数组里每个全量层的位置填 **0**——即"全量层完全不加位置编码，位置信息只存在于滑窗层"：

```jsonc
// config.json: theta=500000 的是滑窗层，0 的是全量层（NoPE）
"layer_rope_theta": [500000.0, 500000.0, 500000.0, 0, 500000.0, ...],
"rope_parameters": { "rope_theta": 500000.0, "rope_type": "default" }
```

课程 Slide 11 讲过"2026 新分歧：位置编码按需分配"（DS-V4 只转最后 64 维、Kimi MLA 层 NoPE）——Muse Glimmer 给出了第四种答案：**按层类型分配**。

**③ FFN：dense SwiGLU**。中间维 19,968 = 3× hidden 6656。dense 结构意味着参数即算力，这与课程"容量与计算解耦"的 MoE 主线相反——Meta 的选择逻辑是端侧显存预算（4-bit 后 <20GB）而非总参数规模。

**④ 归一化 / 稳定化**：Gemma 系 pre/post RMSNorm 布局（`post_norm_eps` 存在）；注意力输出带 **gated attention**（sigmoid 输出门，课程 Slide 31 的"降噪"小件）；`final_logit_softcapping: 20.0`（Gemma 式 logit 软截断）；`qk_scale_factor: 3.87`（QK 打分缩放，作用类似课程 QK-Norm 的"限流阀"但实现不同）。

**⑤ 训推协同：DFlash 块扩散草稿器**。课程 Slide 38 讲过 DSpark 的并行草稿器 DFlash"一次出 γ 个 token、快但会拼出跨模式矛盾"——Muse Glimmer 官方直接标配 DFlash：5 层草稿器、**一次并行预测 16 个 token 的整块**，主模型并行验证。实测加速：RTX 5090 74.9→233.4 tok/s（3.1×）、M4 Max 1.5×、M5 Max 1.8×。另配 4-bit K-Quant（LM <20GB，24/32GB 显存可用，精度损失仅 0.2%/1.0%）。

**多模态**：感知编码器 ~1.8B 的 ViT-G/14（50 层、宽 1536、patch 14，内部同样 window+full 交错，`patch_temporal: 2` 支持视频帧），每图最多 4096 视觉 token，projector 为 2 层 GELU MLP——与课程 Slide 41"切 patch→ViT→projector"三步完全一致。

### 1.3 与课程案例的对比

- 它是课程 Slide 19 三条路线之外的一个**简化变体**：滑窗+全量混合、不加压缩不加稀疏，靠"dense + 极低 KV + 4-bit"换取端侧可用性；
- 全量层 NoPE 与 Kimi-K3 的 MLA 层 NoPE 互为印证：**位置信息可以按层分工**；
- 无 MoE、无 MTP，但把 DFlash 当官方发货配置——推理侧工程比结构创新更激进。

## 2. NVIDIA Nemotron 3.5 Lightning 30B-A3B：Mamba-2 + 注意力 + MoE 三交织

**一句话定位**：课程里的"线性注意力混合"（KDA/Gated DeltaNet）有一个状态空间模型的近亲——NVIDIA 把 **Mamba-2、全量注意力、MoE 三种层交织**在同一网络里，并让课程讲过的 DSpark 成为官方默认投机解码方案。

### 2.1 基本信息

| 项 | 值 |
|---|---|
| 厂商 / 许可证 | NVIDIA / OpenMDW 1.1（商用友好） |
| 规模 | 30B 总参 / **3B 激活**（30B-A3B） |
| 上下文 | 1M token（官方验证） |
| 训练 | 2025-12 ~ 2026-05；预训练数据截止 2025-09 |
| 部署 | 单卡 DGX Spark(GB10) 或 H100；NVFP4 权重（另有 BF16/Base） |

### 2.2 结构拆解（沿五轴线）

**① 注意力：23 Mamba-2 + 6 全量注意力 + 23 MoE，逐层交织**。52 层中 Mamba 层与 MoE 层交替铺开，每 7 层插入 1 层全量注意力兜底精确检索——"线性为主、全量兜底"的课程配方（Kimi 69:24、Qwen 3:1），NVIDIA 给出了 **Mamba-2 版本**：

```jsonc
// config.json（52 层，共 23 mamba + 6 attention + 23 moe）
"layers_block_type": ["mamba","moe","mamba","moe","mamba","attention","moe", ...],
// SSM 配置（Mamba-2 风格：状态维 128、短卷积 4、64 头×64 维）
"ssm_state_size": 128, "conv_kernel": 4, "mamba_num_heads": 64, "mamba_head_dim": 64,
// 全量注意力：GQA 32Q/2KV，head_dim 128，RoPE 全维 θ=10000
"num_attention_heads": 32, "num_key_value_heads": 2, "head_dim": 128, "partial_rotary_factor": 1.0
```

与课程 KDA/Gated DeltaNet 的差别：KDA 是"固定记忆状态 S + 先遗忘再写入"的 delta 规则；Mamba-2 是状态空间模型（SSM），状态方程、离散化方式不同，但共享同一个工程结论——**线性层没有 KV cache，1M 上下文不再爆显存**（推理时用 flashinfer mamba 后端，Mamba cache 存 FP8/FP16 甚至带随机舍入）。

**② MoE：DeepSeek 式细粒度路由**。128 个路由专家、每 token top-6 + 1 个共享专家（`moe_shared_expert_overlap: true`，即共享专家叠加在路由输出上），`norm_topk_prob: true`、`routed_scaling_factor: 2.5`——与课程 DeepSeek-V3 的 sigmoid+noaux 打分、共享专家兜底同源。专家中间维仅 1856，配合 hidden 2688，单 token 激活约 3B。

**③ 激活函数：relu²（平方 ReLU）**。MoE 专家 MLP 用 `relu2` 而非 SwiGLU，Mamba 层用 silu。平方 ReLU 输出天然非负、低精度下行为温和——课程 Slide 30"有界激活家族"（clamp / SiTU）之外，这是第三种"量化友好激活"的工程选择。

**④ 归一化与残差**：`rescale_prenorm_residual: true`（Gemma 式 pre-norm 残差缩放，防止深网信号膨胀，思路与课程 mHC 的"能量守恒"同源但只做标量缩放）。

**⑤ 训推协同：官方三选一投机解码**。这是本模型与课程衔接最紧的一点——课程 Slide 37/38 讲的 MTP 与 DSpark，在这里全部变成**官方发货配置**：

- **DSpark**（课程 Slide 38 的主角，arXiv:2607.05147）：半自回归草稿器 + 置信度调度验证，官方推荐默认（DGX Spark 与低并发数据中心）；
- **DFlash**：块扩散草稿器（同 Muse Glimmer 所用）；
- **MTP**：`mtp_layers_block_type: ["attention","moe"]`，1 层 nextn 模块。
- H100 高吞吐场景官方反而建议**不开投机**——"并行验 4 个 ≈ 串行写 1 个"的前提是 batch 利用率。

另有官方 DSpark/DFlash 草稿器权重仓库（NVFP4-DSpark、NVFP4-DFlash）。

### 2.3 与课程案例的对比

- 课程 Slide 17 说 Kimi/Qwen 选"3 层线性 + 1 层全量"；Nemotron 证明**SSM 家族（Mamba-2）也能顶上"线性层"的位置**，且把 MoE 也拆进交织模式；
- "线性为主 + 全量兜底"从两家扩展到三家，成为 2026 年 8 月开源社区的事实标准配方；
- DSpark 从"DeepSeek 论文方案"升级为"NVIDIA 官方推荐默认"——投机解码进入产品化阶段。

## 3. MiniMax M3（428B）：块级稀疏注意力 MSA + 7 个 MTP 模块

**一句话定位**：GLM-5.2 的 DSA 路线（课程 Part 03/06）在 MiniMax 手里的独立实现——把"逐 token 选 top-k"升级为"**逐块、按 GQA 组分别选 top-k 块**"，并给出系统级算子与 1M 上下文的实测加速。

### 3.1 基本信息

| 项 | 值 |
|---|---|
| 厂商 / 许可证 | MiniMax / minimax-community |
| 规模 | **428B 总参 / ~23B 激活** |
| 上下文 | 1M token，原生多模态（文本+图像+视频，首步即混合模态训练） |
| 论文 | MiniMax Sparse Attention，arXiv:2606.13392 |

### 3.2 结构拆解（沿五轴线）

**① 注意力：MSA（MiniMax Sparse Attention）——DSA 的块级变体**。与 GLM-5.2 索引器思路一致：轻量 Index Branch 打分、只算被选中的位置。差别有三：

- **块粒度**：以 128 token 为一块打分选块（`sparse_block_size: 128`，top-16 块 = 2048 token）；
- **按 GQA 组独立检索**：4 个索引头（dim 128），每个 KV 组选自己的 top-k 块，而非全头共享一个索引；
- **系统级协同**：exp-free top-k 选择 + KV-outer 稀疏注意力算子，把稀疏真正转成 GPU 加速。论文数据：1M 上下文每 token 注意力计算降为 1/28.4，H800 上 prefill 14.2× / decode 7.6×；相对 M2 的 GQA 方案，1M 时 prefill 9×、decode 15×。

```jsonc
// config.json：MSA 索引器配置（前 3 层 dense 不启用索引）
"sparse_attention_config": {
  "use_sparse_attention": true,
  "sparse_index_dim": 128, "sparse_num_index_heads": 4,
  "sparse_topk_blocks": 16, "sparse_block_size": 128
}
```

主注意力为 GQA 64Q/4KV、head_dim 128；**partial RoPE 50%**（rotary 64/128 维，θ=5,000,000）+ **per-head QK-Norm** + Gemma 式 norm——课程 Part 02/05 的全套稳定化小件。

**② MoE：sigmoid + noaux 路由的细粒度专家**。前 3 层 dense（中间维 12288），其余 57 层 MoE：**128 专家 top-4 + 1 共享**（专家中间维 3072），`scoring_func: sigmoid` + `use_routing_bias: true`——正是课程 Slide 23 讲的"DS-V3 无辅助损失 bias 均衡"方案。

**③ 激活：有界 SwiGLU**。`swiglu_alpha: 1.702`、**`swiglu_limit: 7.0`**——与 DS-V4 的 clamp(±10) 同一思路，把 SwiGLU 输出硬限幅到 ±7，为低精度训练兜底（课程 Slide 30 的第三种实现）。

**④ 训推协同：MTP × 7**。config 里 `num_mtp_modules: 7`——课程 GLM-5.2"参数共享 MTP 接受长度 2.76"、Qwen3.6"多步 MTP"之外，MiniMax 直接挂了 **7 个 MTP 模块**，是目前开源模型里 MTP 深度最激进的一档；另有 thinking enabled/adaptive/disabled 三档推理模式。

### 3.3 与课程案例的对比

- MSA 补全了课程 Slide 19 对比表里"DSA"一行：**逐 token 稀疏 → 块稀疏 → 按组块稀疏**，工程约束（Tensor Core 块访问）反过来塑造了算法设计；
- M3 是"课程全家桶"的集大成：noaux 路由 + QK-Norm + partial RoPE + 有界激活 + MTP + 原生多模态，与 GLM-5.2 同源但参数更大、多模态更彻底；
- 对比 GLM-5.2 的 IndexShare（跨层复用索引器）与 M3 的块级 MSA——两家在同一问题（索引器成本）上给了不同答案。

## 4. Qwen3.8：架构"零改动"的一代——训练侧创新成为主战场

**一句话定位**：课程已详讲 Qwen3.6。逐键对比发现：**Qwen3.8-27B 的 config.json 与 Qwen3.6-27B 完全一致（仅 transformers_version 不同）**——这一代的所有增益来自训练与后训练，而非结构。同时 Qwen3.8-Max 首次把 Max 级旗舰权重开源。

### 4.1 逐键对比证据（Qwen3.6-27B vs Qwen3.8-27B）

```text
diff(config_3.6, config_3.8):
  transformers_version: "4.57.1" -> "5.8.0.dev0"   （唯一差异）
```

结构不变：64 层、hidden 5120、16 ×（3 Gated DeltaNet → 1 Gated Attention）、GDN 48V/16QK 头 ×128、GA 24Q/4KV ×256（rotary 64）、FFN 中间维 17408、多步 MTP、上下文 256K 原生（可外推 1M）、27 层原生 ViT。官方模型卡原话："**Built on the architectural foundation of Qwen3.5**"——变化集中在：thinking 开关与 `reasoning_effort` 强度控制、`preserve_thinking` 保留历史思考、Agent 执行与工具反馈处理、端侧适配。

### 4.2 Qwen3.8-Max（2.4T-A95B）：首个开源的 Max 级旗舰

| 项 | 值 |
|---|---|
| 规模 | **2.4T 总参 / 95B 激活**（repo 名 Qwen3.8-2.4T-A95B） |
| 结构 | hidden 8192、92 层、23 ×（3 GDN + 1 全量）、GDN 16QK/128V 头 ×128、GA 64Q/4KV ×256 |
| MoE | **512 专家 top-10**、专家中间维 2048、MTP 1 层 |
| 位置编码 | partial RoPE 25% + M-RoPE（11/11/10，时间/高/宽分维） |
| 上下文 | 262,144（下载版为纯文本 checkpoint，多模态与 1M 保留给 API） |
| 许可证 | **自定义许可**（非 Apache）：月营收 >$20M 或 MAU >1 亿须显著展示模型名；MaaS 类业务 TTM 营收 >$50M 需另行付费许可 |

```jsonc
// Qwen3.8-2.4T-A95B config.json 关键行
"hidden_size": 8192, "num_hidden_layers": 92,
"num_experts": 512, "num_experts_per_tok": 10, "moe_intermediate_size": 2048,
"partial_rotary_factor": 0.25, "mrope_section": [11, 11, 10]
```

### 4.3 与课程案例的对比

- 课程 Slide 42 讲 Qwen3.6 时说过"成熟配方半年内下放"——**3.8 把这个结论推到极致：配方直接冻结，连下放都省了，只换训练**；
- "开源光谱"新现象：同一家族里 27B 是纯 Apache，Max 是收益分成式自定义许可——**开源不再是非黑即白**；
- 对课程的启示：结构评审之外，训练配方（思考保留、agent RL、推理强度控制）已是同等量级的架构变量。

## 5. DeepReinforce Ornith-1.5：Qwen3.5 骨架 + 端到端自改进训练

**一句话定位**：结构上没有任何新东西（397B/35B 就是 Qwen3.5-MoE 骨架，9B 是 Qwen3.5 dense 骨架），全部创新在**训练循环**：任务生成、脚手架构建、解法 rollout 三方联合优化的自改进 RL。

### 5.1 结构事实（配置确认）

| 型号 | 结构 |
|---|---|
| 397B MoE | hidden 4096、60 层、15×（3 GDN+1 全量）、512 专家 top-10、moe_intermediate 1024、GA 32Q/2KV、MTP 1、partial RoPE 25%、ctx 262K、27 层 ViT。激活参数官方未标注 |
| 35B-A3B | 与 Qwen3.5-35B-A3B 同构：hidden 2048、40 层、256 专家 top-8、moe 512；`router_aux_loss_coef: 0.0`（连辅助损失都关掉了） |
| 9B dense | hidden 4096、32 层、FFN 12288、27 层 ViT，量化版可上手机 |

### 5.2 真正的变量：自改进训练闭环

官方模型卡：Ornith-1.0 基于 **Qwen3.5 与 Gemma 4** 骨架做继续预训练（CPT）+ mid-training + post-training；Ornith-1.5 把自改进循环从"脚手架与 rollout 优化"扩展为**联合优化任务生成、脚手架构建与解法 rollout**——模型自己提出新任务、生成任务专属脚手架（scaffold）、产出 rollout 并用 RL 改进策略，不再依赖人工整理的任务集与手工 harness。

效果（官方口径）：Terminal-Bench 2.1 86.1（Claude Opus 4.8 为 85.0）、DeepSWE 56.0（Opus 59.0），超过同量级开源 GLM-5.2 与 DeepSeek-V4-Flash-0731；MIT 许可。

### 5.3 与课程案例的对比

- 印证课程 Slide 33 的核心论断："**架构、优化器、训练配置是一个耦合系统，评价任何改动都要说明在什么训练配置下**"——Ornith 用同一个 Qwen 骨架，仅凭训练侧改动就做出旗舰级分数；
- "自改进/自训练"是课程未展开的新方向：从"人工造数据"到"模型生成任务+脚手架+rollout"的闭环，可能成为下一期课程的主题；
- 对调研作业的方法论提示：**读 config.json 只能看到一半故事，训练循环是另一半**。

## 6. 零一万物 Ling-3.0：KDA × MLA 杂交的"百灵"混合架构

**一句话定位**：课程两大注意力路线的**杂交品种**——把 Kimi 的 KDA 线性层与 DeepSeek 的 MLA 压缩注意力按 3:1 / 5:1 交替堆叠，配细粒度 MoE，主打低激活参数的端侧/生产部署。

### 6.1 基本信息

| 项 | Ling-3.0-tiny | Ling-3.0-flash |
|---|---|---|
| 规模 | **7.9B 总 / 1.3B 激活** | **124B 总 / 5.1B 激活** |
| 层布局 | 24 层 = 6×（3 KDA + 1 MLA） | 42 层 = 35 KDA + 7 Gated MLA + 2 dense |
| MoE | 128 专家 top-8 + 1 共享（中间维 512） | 512 专家 + 1 共享（中间维 768，官方称"1/64 稀疏"） |
| 上下文 | 128K | 256K |
| MTP | 无 | 1 层 |
| 部署成绩 | DGX Spark ~100-105 tok/s、M4 Pro 86-90 tok/s、8.34 GiB@8K | 对标准前代 1T 旗舰 Ring-2.6（激活仅其 8.1%） |

### 6.2 结构拆解（沿五轴线）

**① 注意力：KDA（Kimi 路线）+ MLA（DeepSeek 路线）交替**。config 直接暴露 MLA 的低秩参数（与课程 Slide 14 的 Kimi MLA 结构同型）：

```jsonc
// Ling-3.0-tiny config.json：MLA 低秩 + KDA 配置
"kv_lora_rank": 512, "q_lora_rank": 256,
"qk_head_dim": 192, "qk_nope_head_dim": 128, "qk_rope_head_dim": 64,
"kda_lower_bound": -5, "kda_safe_gate": true, "short_conv_kernel_size": 4
```

KDA 的衰减门下界 **−5** 与 Kimi-K3 相同（课程 Slide 40 讲过该数值的来由：保证 16-token tile 内累积衰减落在 BF16 动态范围）；flash 版还升级了"KDA 细粒度对角门控"。**位置编码**：partial RoPE 50%（rotary 64/128，θ=6,000,000）+ QK-Norm。

**② MoE：sigmoid + noaux 全套**。`scoring_func: sigmoid`、`topk_method: noaux_tc`、`moe_router_enable_expert_bias: true` + `seq_aux: true`、`routed_scaling_factor: 2.5`、前 1~2 层 dense——课程 Slide 23 方案的完整落地。

**③ 有界激活**：flash 的 config 里 `expert_swiglu_limit_list` 后 6 层为 **4.0**（其余为 0=不限幅）——课程 Slide 30"clamp(-10,10)"的轻量版，只对部分层的专家输出限幅。

**④ 训推协同（flash）**：MTP 1 层；部署侧集成 **SGLang HiCache + Mooncake 分层缓存**（物理双池 + 集群共享 L3），长输入场景 TTFT 降低 60%~80%；用 10,000+ 交互式环境训练 Agent 闭环。

### 6.3 与课程案例的对比

- 课程 Slide 17 说"线性为主、全量兜底"，Ling 的答案是"**线性为主、MLA 兜底**"——把全量注意力换成压缩注意力，KV cache 进一步下探；
- 它同时证明了课程两条主线（KDA 与 MLA）**可以混血**，且 tiny 版 1.3B 激活 + MacBook 部署把"低激活 + 端侧"卷到新低；
- flash 的"部分层 SwiGLU 限幅"提示：稳定化手段也走向按层细粒度配置（同 Muse Glimmer 按层 NoPE 一个趋势）。

## 8. 结论：这些"没讲的"模型补全了课程的哪几块拼图

**（一）"线性为主 + 全量兜底"泛化，且出现第四种混合来源。** 课程里的线性层只有 KDA（Kimi）与 Gated DeltaNet（Qwen）；Nemotron 证明 **Mamba-2 状态空间层**同样能顶上（并与 MoE、注意力三层交织），Ling 证明 **KDA 与 MLA 可以杂交**。"全量兜底层"也被替换实验过：Ling 用 MLA 兜底、Muse Glimmer 用 1/4 全量层兜底且只给它们 2048 滑窗。

**（二）位置编码"按需分配"成为标配而非例外。** 课程只举了三例（partial 64 维 / 25% / NoPE），本周又添两例：Muse Glimmer **按层**分配（局部 RoPE、全局 NoPE），MiniMax/Ling **按维度比例**分配（50%）。"给多少位置信息"确如课程所言是设计旋钮。

**（三）有界激活家族扩容。** 课程只有 clamp(±10) 与 SiTU 两种；新增 SwiGLU-limit（M3=7.0、Ling=4.0，且可逐层配置）与 **relu²**（Nemotron）。低精度训练时代，"激活不出离群点"与"深网不炸"一样成为硬需求。

**（四）架构收敛、训练与推理工程成为主战场。** 最硬的证据：Qwen3.8-27B 与 3.6 **配置逐键全同**；Ornith 借 Qwen3.5 骨架只改自改进训练闭环；Meta 用蒸馏 + DFlash 端侧化；NVIDIA 把课程讲过的 DSpark 做成官方默认配置。这验证了课程 Slide 33/42 的两条论断：评价架构必须带上训练配置；成熟配方从发表到工程成熟的周期在缩短。

**（五）两条课程未覆盖的新轴线：端侧化与开源光谱。** 6 组模型里 5 组主打消费级硬件（24GB 显卡、DGX Spark、MacBook、甚至手机量化版）；许可证从纯 Apache/MIT 扩展到 OpenMDW、minimax-community 与 Qwen3.8-Max 的收益分成条款——"开源权重"本身正在分层，未来调研作业应把许可证条款纳入模型对比维度。
