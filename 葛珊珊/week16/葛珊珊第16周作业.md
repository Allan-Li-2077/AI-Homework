# Grok / Gemini / Llama 三大系列大模型架构调研

> 调研时间：2026 年初 ｜ 覆盖范围：xAI Grok、Google DeepMind Gemini、Meta Llama 三个主流大模型家族的架构演进、核心技术参数与设计理念。

## 1. 总览：三大模型家族对比速览

| 维度 | Grok（xAI） | Gemini（Google DeepMind） | Llama（Meta） |
|---|---|---|---|
| 首个版本 | Grok-1（2023-11，开源 2024-03） | Gemini 1.0（2023-12） | Llama 1（2023-02） |
| 最新版本（截至调研） | Grok-4（2026-01） | Gemini 3 Pro（2025-11） | Llama 4（2025-04） |
| 核心架构 | MoE（混合专家） | MoE（混合专家） | Dense → MoE（Llama 4 起） |
| 开源情况 | Grok-1/Grok-2 开源，Grok-3/4 闭源 | 闭源（API/产品化） | 全系开源（最成功的开源 LLM 家族） |
| 多模态 | 文本为主（Grok-2 起支持图像生成） | 原生多模态（文本/图像/音频/视频/代码） | Llama 1–3 纯文本，Llama 3.2/4 支持视觉 |
| 典型上下文长度 | Grok-1 为 8K，后续版本大幅增强 | 1M–2M tokens | 128K（Scout 演示 10M） |
| 特色 | 实时访问 X 平台数据、强推理 | 原生多模态、超长上下文、Agentic | 开放权重、生态完善、GQA/RoPE 标准制定者之一 |
| 训练基础设施 | Colossus 超算（约 20 万块 H100） | TPU（v4/v5e/v5p/Trillium） | GPU 集群（公开披露） |

## 2. Grok 系列（xAI）

### 2.1 家族谱系

| 版本 | 发布时间 | 参数量 | 架构 | 说明 |
|---|---|---|---|---|
| Grok-1 | 2023-11 发布，2024-03 开源 | 314B（激活约 78–86B） | MoE，8 专家 / Top-2 | 首个开源版本，纯基座模型 |
| Grok-1.5 | 2024-03 | 未披露 | MoE（推测） | 改进推理与长上下文 |
| Grok-2 / Grok-2 Mini | 2024-08 发布，2025-03 开源 | 未披露 | MoE（推测） | 增强代码/推理，集成 FLUX.1 图像生成 |
| Grok-3 / Mini / Fast | 2025-02 | 未披露（外界传闻约 2T） | MoE | 引入思维链（CoT）推理，深度推理模式 |
| Grok-3.5 | 2025-11 | 未披露 | MoE | 系列小幅迭代（标准/快速/推理版） |
| Grok-4 | 2026-01 | 未披露 | MoE | 最新旗舰，传闻强化多智能体协作 |

### 2.2 Grok-1：唯一公开全部架构细节的版本

Grok-1 于 2024 年 3 月开源权重，是当时参数量最大的开源 MoE 模型，也是了解 Grok 系列底层设计的唯一官方窗口。核心参数如下（来自 [xai-org/grok-1 官方仓库](https://deepwiki.com/xai-org/grok-1/3-model-architecture)）：

| 参数项 | 数值 |
|---|---|
| 总参数量 | 314B |
| 架构 | MoE（Mixture of Experts） |
| 专家数量 | 8 个专家，每 token 路由激活 2 个（Top-2） |
| 每 token 激活参数 | 约 86B（约占总数 1/4，等效计算量约 86B 稠密模型） |
| Transformer 层数 | 64 层 |
| 注意力头数 | 48 个 Q 头 / 8 个 KV 头（GQA 分组查询注意力） |
| Hidden size | 6144 |
| 词表大小 | 131072（128K，BPE 分词） |
| 上下文长度 | 8192 tokens |
| 位置编码 | RoPE（旋转位置编码） |
| 训练数据 | 约 13T tokens（截至 2023 年 Q4，含网络爬虫 + X/Twitter 实时数据） |
| 训练方式 | 纯预训练基座模型（无 RLHF / 无指令微调） |

**设计要点：**
- **MoE + GQA 组合**：通过稀疏激活（8 选 2）在 314B 总参数下把单 token 计算量压到 ~86B 稠密当量，同时用 GQA 显著降低 KV 缓存与解码显存开销。
- **数据差异化**：训练数据大量来自 X 平台实时流，赋予模型极强的"时事知识"与网络梗理解能力，这是 Grok 区别于其他模型的独有优势。
- **发布即开源**：Grok-1 以 Apache 2.0 协议开源，但**未包含微调/RLHF 版本**，是"原始预训练权重"，社区评价其开箱即用性一般。

### 2.3 Grok-2：能力跃升，仍保持神秘

- 2024 年 8 月发布，2025 年 3 月开源（Grok-2 及 Grok-2 Mini）。
- **官方未披露任何架构参数**，业界普遍推测延续 MoE 架构，参数量级在 314B 以上。
- 主要改进：代码生成、数学推理、指令遵循大幅增强；集成 FLUX.1 文本生图模型，支持文生图。
- 训练基础设施：xAI 自建 **Colossus 超算**（第一阶段约 10 万块 H100，后扩展至约 20 万块），这也是后续 Grok-3 训练的基础。
- 发布时在 LMSYS Chatbot Arena 盲测中位列前茅，一度超过 GPT-4 与 Claude 3.5。

### 2.4 Grok-3：强化推理，史上最大算力训练

- 2025 年 2 月发布，宣称"全球最强 AI 模型"，与 Grok-3 Mini、Grok-3 Fast 一同上线。
- **参数量未公布**，外界多传闻总参数约 2T、仍为 MoE（未获官方证实）。
- 训练算力：Colossus 超算（约 20 万块 H100），官方称训练算力约为 Grok-2 的 **10 倍**。
- 关键创新：
  - **思维链（Chain-of-Thought）推理模式**：可切换"深度思考"（长 CoT，逐步推理）与"快速回答"两种模式，用户可显式关闭思维链输出。
  - **强化学习体系**：后训练采用 RLHF + RLVR（基于可验证奖励的强化学习，规则校验数学/代码结果），显著提升数学与代码能力。
  - **实时数据接入**：继承并强化实时抓取 X 平台数据的能力。
- 代表性基准表现（官方发布数据）：AIME 2025 数学 93.3、GPQA Diamond 科学 84.6、LMArena Elo 约 1402。

### 2.5 Grok-4：最新旗舰（2026-01）

- 2026 年 1 月发布，为当前 Grok 系列最新旗舰，架构细节未公开（推测 MoE + 强化推理）。
- 部分行业报道提及 Grok-4 系列引入**多智能体系统**（如多 Agent 辩论/协作机制）与更深的 X 平台生态整合。
- 后续还有 Grok 4.x 系列小版本迭代（4.4/4.5 等）的传闻。

### 2.6 Grok 系列架构小结

```
输入 tokens
   │
   ▼
[ Embedding (词表 128K) ]
   │
   ▼
64 × Transformer 层（每层）：
   ├─ RMSNorm（Pre-Norm）
   ├─ 多头注意力（48 Q 头 / 8 KV 头, GQA）+ RoPE
   ├─ RMSNorm
   └─ MoE FFN：8 个专家（Top-2 路由激活）
   │
   ▼
[ 输出层 / Softmax ]
```

## 3. Gemini 系列（Google DeepMind）

### 3.1 家族谱系

| 版本 | 发布时间 | 参数量 | 架构 | 说明 |
|---|---|---|---|---|
| Gemini 1.0（Ultra/Pro/Nano） | 2023-12 | 未披露（Nano-1=1.8B，Nano-2=3.25B） | Decoder-only，推测 MoE | 原生多模态，MMLU 首超人类专家 |
| Gemini 1.5 Pro / Flash | 2024-02 / 2024-04 | 未披露 | **Sparse MoE，8 个专家（技术报告确认）** | 1M tokens 上下文，长上下文里程碑 |
| Gemini 2.0（Flash/Flash-Lite/Pro） | 2024-12 / 2025-01 | 未披露 | MoE（推测） | 原生 Agentic，低延迟高吞吐 |
| Gemini 2.5 Pro / Flash / Flash-Lite | 2025-03 / 2025-06 | 未披露 | MoE（推测） | "Thinking" 显式推理模式，技术白皮书发布 |
| Gemini 3 Pro | 2025-11 | 未披露 | MoE（多方报道确认） | 2M context、混合推理、Agentic 强化 |

### 3.2 Gemini 1.0：原生多模态的开端

- 2023 年 12 月发布，提供 Ultra（最强）/ Pro（均衡）/ Nano（端侧）三档，覆盖云端到手机（Pixel）。
- **原生多模态（Natively Multimodal）**：模型从预训练起就统一处理文本、图像、音频、视频、代码，而非"拼接"各单模态模型。图像/音频/视频先经各自编码器（如语音用 USM 类编码器）转为 token 序列，再送入 decoder-only Transformer 主网络。
- 架构细节未公开（技术报告不披露参数量与层数），业界推测同样采用 MoE。
- 里程碑：Gemini Ultra 在 MMLU 上以 90.04% 首次超越人类专家水平。
- Nano 版本明确公开：Nano-1（1.8B）、Nano-2（3.25B），面向端侧推理（蒸馏自大模型）。

### 3.3 Gemini 1.5：技术报告确认 MoE 与百万上下文

Gemini 1.5 系列（Pro 于 2024-02、Flash 于 2024-04 发布）是架构信息公开度最高的一代，[技术报告](https://m.thepaper.cn/newsDetail_forward_26368885) 确认以下关键点：

- **Sparse MoE 架构，8 个专家**：延续 Gemini 1.0 的稀疏混合专家路线，单 token 仅激活部分专家，兼顾模型容量与推理效率。
- **超长上下文：1M tokens（实验 10M）**：可一次处理 1 小时视频、11 小时音频、70 万词文本或 3 万行代码，是当时最强的长上下文模型。
- **训练数据规模**：1.5 Pro 训练于约 10.5T tokens（2023 年采集的文本/图像/音频/视频数据）；1.5 Flash 为约 3.5T tokens。
- **Flash 定位**：更轻量、更低延迟、高吞吐的性价比版本，主打规模化服务。
- **多阶段训练**：预训练 → 监督微调（SFT）→ 人类反馈强化学习（RLHF）→ 基于偏好对（preference pairs）的对齐训练。

### 3.4 Gemini 2.0：原生 Agentic

- 2024 年 12 月发布 Gemini 2.0 Flash / Flash-Lite，2025 年 1 月推出 2.0 Pro。
- 主打**原生智能体（Agentic）能力**：工具调用、代码执行、多模态理解与生成一体化，可直接操作外部工具与应用。
- 架构细节未披露，推测延续 MoE；Flash-Lite 面向极致性价比场景。
- 多模态进一步升级：支持图像/视频生成输入理解、实时音视频流式理解。

### 3.5 Gemini 2.5：Thinking 推理模式

- 2025 年 3 月发布 Gemini 2.5 Pro，6 月发布 Flash / Flash-Lite；7 月发布 [技术白皮书（arXiv:2507.06261）](https://ar5iv.labs.arxiv.org/html/2507.06261v6)。
- **核心创新："Thinking" 显式推理模式**：模型先产出内部思维链再作答，可控制推理预算（思考时间越长，推理越强）；这是 Gemini 首次将 CoT 推理产品化。
- 2.5 Pro：默认 1M tokens 上下文（实验版 2M），多模态输入 + 文本输出。
- 2.5 Flash：推理能力与成本/延迟的平衡点；另有 2.5 Deep Think（超长思考，数学/科学极限推理）。
- 发布时在 LMArena、GPQA、MMMU 等多模态与推理基准登顶。

### 3.6 Gemini 3 Pro：最新旗舰（2025-11-18）

- 发布即登顶多项基准，**2M tokens 上下文**，原生多模态 + Agentic 能力全面强化。
- **混合推理（Hybrid Thinking）**：简单问题快速作答（"闪电推理"），复杂问题自动切换深度思考，动态分配推理预算。
- 多方技术报道确认仍基于 **MoE 架构**，具体参数未披露。
- 训练于 Google 自研 TPU 集群（v4/v5e/v5p，旗舰训练集群为 v6 Trillium）。

### 3.7 Gemini 系列架构小结

```
输入（文本 tokens / 图像 patches / 音频帧 / 视频帧 / 代码）
   │        （各模态经独立编码器统一映射到共享 token 空间）
   ▼
[ 共享 Embedding 空间 ]
   │
   ▼
N × Transformer 层（MoE，8 专家，稀疏激活）：
   ├─ 多模态联合注意力（跨模态注意力，覆盖 1M–2M 上下文）
   ├─ 稀疏 MoE FFN
   └─ 长上下文技术（注意力稀疏化 / 内存优化）
   │
   ▼
[ 输出层：文本 / 图像 / 音频 token ]
```

## 4. Llama 系列（Meta AI）

### 4.1 家族谱系与全系列参数表

Llama 是**开源大模型的标杆**，也是社区复现架构事实标准（RoPE + RMSNorm + SwiGLU + GQA 组合）的源头之一。

| 版本 | 参数量 | 层数 | Hidden size | Q 头 / KV 头 | 词表 | 上下文 | 架构 |
|---|---|---|---|---|---|---|---|
| Llama 1（2023-02） | 7B / 13B / 33B / 65B | 32/40/60/80 | 4096/5120/6656/8192 | 全 MHA | 32000 | 2048 | Dense |
| Llama 2（2023-07） | 7B / 13B / 70B | 32/40/80 | 4096/5120/8192 | 70B 用 GQA（8 KV 头） | 32000 | 4096 | Dense |
| Llama 3（2024-04） | 8B / 70B | 32 / 80 | 4096 / 8192 | 全系 GQA（8 KV 头） | **128256** | 8192 | Dense |
| Llama 3.1（2024-07） | 8B / 70B / **405B** | —/—/**126** | —/—/**16384** | —/—/128 头 8 KV | 128256 | **131072（128K）** | Dense |
| Llama 3.2（2024-09） | 1B / 3B（文本）；11B / 90B（视觉） | — | — | — | 128256 | 128K | Dense + Vision |
| **Llama 4 Scout**（2025-04） | **109B 总 / 17B 激活** | — | — | — | — | 128K（演示 10M） | **MoE，16 路由专家** |
| **Llama 4 Maverick**（2025-04） | **400B 总 / 17B 激活** | — | — | — | — | 128K（演示 1M） | **MoE，128 路由专家** |
| **Llama 4 Behemoth**（未发布） | **2T 总 / 288B 激活** | — | — | — | — | — | **MoE，16 路由专家** |

### 4.2 Llama 1 / 2：奠定开源 LLM 架构基线

**Llama 1（2023-02，论文 [LLaMA: Open and Efficient Foundation Language Models](https://ar5iv.labs.arxiv.org/html/2505.08137)）**
- 纯 Decoder-only Transformer，确立四个"标配"：**Pre-Norm + RMSNorm**（替代 LayerNorm）、**SwiGLU 激活**、**RoPE 旋转位置编码**、**无 bias**。
- 词表 32K（SentencePiece BPE），上下文 2K，训练数据 1.4–1.5T tokens。
- 开源即引爆社区（alpaca、Vicuna、LoRA 等生态由此爆发）。

**Llama 2（2023-07）**
- 上下文扩至 4K，训练数据增至 2T tokens。
- **70B 引入 GQA（8 个 KV 头）**，显著降低解码显存与 KV 缓存开销，成为后续超大模型标配。
- 首次附带 RLHF 对齐版本（Llama-2-chat），商用许可放开，推动企业级应用。

### 4.3 Llama 3 / 3.1 / 3.2：Dense 架构的巅峰

**Llama 3（2024-04，8B / 70B）**
- 词表升级到 **128256**（tiktoken 类 BPE），多语言与代码能力大幅提升。
- **全系 GQA**（8 个 KV 头）；训练数据 15T+ tokens（较 Llama 2 提升 7.5 倍）。
- 8B：32 层 / hidden 4096；70B：80 层 / hidden 8192。

**Llama 3.1（2024-07，8B / 70B / 405B）**
- 上下文统一扩至 **128K**，支持 8 种语言，内置工具调用（function calling）。
- **405B 是当时最大开源 Dense 模型**：126 层 / hidden 16384 / 128 Q 头 + 8 KV 头，训练于 15.6T tokens；在 16K 个 H100 上训练，采用 4D 并行（TP+PP+CP+DP）与 FP8。
- 引入知识蒸馏（8B/70B 部分能力蒸馏自 405B）与"Llama 3.1 系统"（安全模型 + 工具 + 多语言）。

**Llama 3.2（2024-09）**
- 纯文本小模型 1B / 3B（端侧推理），以及**首批视觉模型 11B / 90B**（视觉塔基于 CLIP 类编码器 + 适配器接入文本主干；90B 由 405B 剪枝、11B 由 70B 剪枝）。
- 视觉模型支持文档/图表/图像理解。

### 4.4 Llama 4：首次 MoE + 原生多模态（2025-04）

Llama 4 是 Meta 架构路线的大转折，发布 Scout（109B/16E）与 Maverick（400B/128E）两个开源模型，另有 2T 的 Behemoth（未发布）。核心技术细节参见 [Llama 4 技术文档](https://export.arxiv.org/pdf/2601.11659)：

- **首次采用 MoE**：
  - Scout：总参数 109B，**每 token 激活约 17B**，16 个路由专家 + 共享专家。
  - Maverick：总参数 400B，**每 token 激活约 17B**，128 个路由专家 + 共享专家。
  - Behemoth：总参数 2T，激活约 288B，16 个路由专家。
- **早期融合（Early Fusion）原生多模态**：视觉编码器（VQ-VAE 类 tokenizer + 自回归图像编码）直接把图像 token 注入主模型，与文本 token 一起预训练，无需后期拼接。
- **iRoPE（Interleaved RoPE）**：注意力层**交替使用/不使用 RoPE**，利用部分层"无位置编码"的自由度提升超长上下文外推能力——这是 Llama 4 长上下文（Scout 可演示 10M tokens）的核心技术。
- **大 MoE 表（Big MoE Table）**：跨层共享的路由权重表，专家负载更均衡，并显著压缩 KV 缓存占用。
- **KV 缓存量化压缩**：降低长上下文推理的显存需求。
- 训练规模：Maverick 训练于约 32T tokens（30T+，多语言多模态），Scout 规模更小；支持 12 种语言。
- 上下文：Scout 支持 128K（在特定硬件配置下可演示 10M tokens）；Maverick 支持 128K（可演示 1M）。

### 4.5 Llama 系列架构演进小结

```
Llama 1 ──► Dense，确立 RMSNorm + SwiGLU + RoPE + 无 bias
Llama 2 ──► + GQA（70B），+ RLHF，上下文 4K
Llama 3 ──► 词表 128K，全系 GQA，15T tokens，上下文 8K
Llama 3.1 ─► 405B Dense 巅峰，128K 上下文，工具调用
Llama 3.2 ─► 视觉模型（11B/90B），小模型（1B/3B）
Llama 4 ──► 转 MoE（109B/16E、400B/128E），iRoPE，早期融合多模态
```

## 5. 三大系列横向对比

### 5.1 架构路线对比

| 对比项 | Grok | Gemini | Llama |
|---|---|---|---|
| 主干架构 | MoE（8 专家起） | MoE（8 专家起） | Dense（1–3.1）→ MoE（4） |
| 注意力机制 | GQA（8 KV 头） | 长上下文稀疏注意力 | GQA（KV 头压缩）+ 稀疏注意力 |
| 位置编码 | RoPE | 未披露（推测长上下文方案） | RoPE → iRoPE（Llama 4） |
| 归一化 | RMSNorm | 未披露（推测 RMSNorm 类） | RMSNorm（Pre-Norm） |
| 激活函数 | SwiGLU | 未披露 | SwiGLU |
| 词表 | 128K（Grok-1） | 未披露（SentencePiece 类） | 32K → 128K |
| 多模态 | 文本为主 | 原生多模态（最强） | Llama 3.2+ 支持视觉 |

### 5.2 共性技术（三大系列不约而同的选择）

1. **Decoder-only Transformer**：三大家族全部采用自回归解码器架构，这是 2023 年后大模型的绝对主流。
2. **RoPE 旋转位置编码**：Grok-1、Llama 全系采用；Gemini 未披露但大概率同类，说明 RoPE 是长上下文时代的"事实标准"。
3. **RMSNorm + Pre-Norm**：训练更稳定、省显存。
4. **SwiGLU 激活**：提升 FFN 表达力。
5. **GQA 分组查询注意力**：以极小精度代价大幅压缩 KV 缓存，是支撑长上下文与高吞吐的关键工程手段。
6. **向 MoE 收敛**：Grok 与 Gemini 从一开始就是 MoE，Llama 4 也转向 MoE——**"大总参数 + 稀疏激活"是超大模型的主流路线**。

### 5.3 差异化定位

| 维度 | Grok | Gemini | Llama |
|---|---|---|---|
| 独家数据 | X 平台实时流 | 多模态语料（YouTube、多语言） | 公开网络 + 授权数据（开源透明） |
| 推理特色 | 显式 CoT（Grok-3 起） | "Thinking" 推理预算控制（2.5 起） | 无内置 CoT，依赖 RL 提升 |
| 生态 | 深度绑定 X / 特斯拉 | Google 全家桶（Search、Workspace、Android） | 开源生态之王（HF、Ollama、vLLM 全支持） |
| 部署形态 | 闭源 API + 开源权重（部分） | 闭源 API | 全开源权重，可私有化部署 |
| 训练算力 | 约 20 万 H100（Colossus） | TPU v4–v6（Trillium） | H100 集群（409B 用 16K H100） |

## 6. 关键结论

1. **架构趋同化**：三大系列的底层骨架高度一致（Decoder-only + RMSNorm + SwiGLU + RoPE + GQA），差异化主要体现在**稀疏化（MoE）、多模态融合方式、上下文工程与推理训练（CoT/RL）**上。
2. **MoE 成为大模型标配**：Grok、Gemini 全程 MoE，Llama 4 跟进；"几百 B 到几 T 的总参数、十几个 B 的激活参数"成为旗舰模型的常见形态。
3. **长上下文是共同军备竞赛**：Grok-1 的 8K → Gemini 的 1M–2M → Llama 4 Scout 演示 10M，上下文能力每代提升一个数量级。
4. **推理（Reasoning）成为新战场**：Grok-3 的 CoT、Gemini 2.5 的 Thinking、Llama 4 的 RL 强化，三大厂商都把"思考能力"作为下一代旗舰的核心卖点。
5. **开源策略分化**：Llama 全开放、Grok 选择性开放（1/2 开源、3/4 闭源）、Gemini 全闭源，构成当前开源与闭源生态的三种典型路径。
