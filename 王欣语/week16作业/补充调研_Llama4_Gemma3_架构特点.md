# 开源大模型结构特点调研报告（补充）

> 调研对象：Llama 4 (Meta) & Gemma 3 (Google)

---

## 一、Llama 4 系列 (Meta, 2025年4月发布)

### 1.1 模型概述

Llama 4 是 Meta 发布的最新开源大模型系列，采用 **MoE（混合专家）架构**，包含三个版本：

| 模型 | 总参数量 | 专家数量 | 上下文长度 | 定位 |
|------|----------|----------|------------|------|
| **Llama 4 Scout** | 17B | 16个专家 | 256K | 轻量高效，适合端侧 |
| **Llama 4 Maverick** | 400B | 128个专家 | 256K | 高性能多模态 |
| **Llama 4 Behemoth** | 2T | 288个专家 | 256K | 教师模型（不对外发布） |

> 注：Scout 总参数量 17B，但推理时仅激活部分专家，实际计算量小于 17B。

### 1.2 核心架构特点

#### 特点1：iRoPE 位置编码 —— 实现 256K 长上下文

**传统问题**：模型训练时通常使用 8K 或 16K 长度的文本，直接处理 256K 长文本时，位置编码超出训练分布，导致模型对长距离位置关系建模能力下降。

**Llama 4 的解决方案（iRoPE）**：
- 对位置编码进行插值压缩，将 256K 的位置范围映射到模型熟悉的 8K 范围内
- 保持相对位置关系的连续性，使模型无需额外训练即可处理更长上下文

**与教学项目中模型的对比**：
- DeepSeek-V4 用 **CSA+HCA**（动态压缩不重要内容）
- Kimi K3 用 **KDA**（只记录变化量）
- Llama 4 的 iRoPE 通过位置编码插值实现，实现简单，支持 256K 上下文

#### 特点2：原生多模态 —— 视觉与语言共享 Transformer 骨干

**传统做法（如 Kimi K3）**：
1. 用独立视觉编码器提取图片特征 → 2. 通过投影层将视觉特征转换为文本表示 → 3. 输入给语言模型处理
- 信息经过中间转换，存在信息损失

**Llama 4 的做法**：
- 视觉和语言共享同一个 Transformer 骨干网络
- 图片和文本 token 从输入层就统一处理，无需额外的投影转换层
- 视觉特征和语言特征在同一空间内交互，减少信息损失

#### 特点3：MoE 架构 —— 每个 token 激活 2 个专家

**Llama 4 的路由策略**：
- 总共 16~128 个专家，每个 token 通过路由网络选择 **2 个最相关的专家** 处理
- 激活专家数量少，路由决策开销低，推理效率高

**与教学项目中模型的对比**：

| 模型 | 专家总数 | 激活专家数 | 策略特点 |
|------|----------|------------|----------|
| Llama 4 | 16~128 | 2 | 少而精，注重匹配准确度 |
| DeepSeek-V4 | 256 | 8 | 中等数量，平衡覆盖和效率 |
| Kimi K3 | 896 | 16 | 多而广，追求知识覆盖全面 |
| Qwen3.6 | 256 | 8 | 中等数量，标准配置 |

**差异理解**：
- Llama 4 采用少专家激活策略，认为精准匹配 2 个专家比泛化激活 8 个专家效果更好
- 中国模型（DeepSeek/Kimi/Qwen）倾向于多激活专家，通过增加覆盖范围确保知识不遗漏

#### 特点4：GQA —— 减少 KV Cache 显存占用

**问题**：模型生成文本时，需要缓存之前所有 token 的 Key 和 Value（KV Cache），长序列下显存占用大。

**GQA 的解决思路**：
- 多个 Query 共享同一组 Key/Value，减少 KV Cache 的存储量
- 例如 8 个 Query 头共享 1 组 KV，显存占用降至原来的 1/8
- 在推理速度和模型质量之间取得平衡

**与教学项目中模型的对比**：
- DeepSeek-V3/V4 用 **MLA**（把记忆压缩成低维向量，更极致）
- Kimi K3 用 **KDA**（只记变化量）
- Llama 4 的 GQA 实现简单，工程成熟度高，效果稳定

### 1.3 训练方法亮点

#### 模型蒸馏：大模型教小模型

**流程**：Behemoth（2T，不发布）→ Maverick（400B）→ Scout（17B）

**技术说明**：
- 先训练最大规模的教师模型 Behemoth（2T 参数），掌握全面知识但推理成本过高
- 教师模型为较小模型（Maverick/Scout）生成训练数据和软标签（logits）
- 小模型通过模仿教师的行为分布，在较小规模下获得接近大模型的能力

### 1.4 简单总结

| 维度 | Llama 4 的特点 |
|------|---------------|
| 架构风格 | 简洁实用，不追求极致 |
| 长上下文 | 256K 够用就好，用简单方法实现 |
| 多模态 | 原生融合，非拼接 |
| MoE | 少激活专家（2个），注重精准 |
| 注意力优化 | GQA，简单高效 |
| 定位 | 易部署、易使用、多模态友好 |

## 二、Gemma 3 系列 (Google, 2025年3月发布)

### 2.1 模型概述

Gemma 3 是 Google 推出的轻量级开源模型，基于 Gemini 2.0 技术，特点是**小参数、高效率、全多模态**：

| 模型 | 参数量 | 上下文长度 | 支持多模态 | 定位 |
|------|--------|------------|------------|------|
| **Gemma 3 1B** | 1B | 128K | 是 | 超轻量，手机可跑 |
| **Gemma 3 4B** | 4B | 128K | 是 | 轻量高效 |
| **Gemma 3 12B** | 12B | 128K | 是 | 平衡性能 |
| **Gemma 3 27B** | 27B | 128K | 是 | 最强版本 |

> 注：所有版本都支持图片理解，这是 Gemma 3 的一大特色。

### 2.2 核心架构特点

#### 特点1：知识蒸馏 —— 小模型学大模型

**Gemma 3 的特殊之处**：
- 训练全程都有教师模型（Gemini 2.0）参与，而非仅在最后阶段蒸馏
- 教师不仅提供最终答案，还提供中间推理过程的监督信号
- 小模型在训练各阶段都能获得教师指导，学习效果更稳定

**与 Llama 4 蒸馏的对比**：

| 对比项 | Llama 4 蒸馏 | Gemma 3 蒸馏 |
|--------|-------------|-------------|
| 老师模型 | 2T 的 Behemoth | Gemini 2.0（规模未公开） |
| 教学方式 | 最后阶段单独教 | 全程陪伴式教学 |
| 学生规模 | 17B ~ 400B | 1B ~ 27B |
| 目标 | 大模型变小 | 小模型变强 |

#### 特点2：Local-Global 注意力 —— 高效处理长文本

**问题**：128K 文本的全局自注意力计算量大，每层的注意力计算涉及所有 token 对，计算和显存开销随序列长度平方增长。

**Gemma 3 的解决思路**：
- **Local（局部）**：每个 token 主要关注邻近窗口内的 token（如前后 4K 范围）
- **Global（全局）**：少量特殊 token（如 [CLS]、段落标记）可以访问全部内容，承担全局信息聚合角色
- 通过减少全局注意力计算量，降低长序列处理开销

**与教学项目中模型的对比**：
- DeepSeek-V4 用 **CSA+HCA**：动态判断哪些内容重要，压缩不重要的
- Kimi K3 用 **KDA**：只记变化，不重复记相同内容
- Gemma 3 的 Local-Global 用固定规则区分局部和全局，实现简单，效果稳定

#### 特点3：软注意力掩码 —— 连续注意力权重

**传统做法**：
- 注意力掩码是二值的：每个 token 要么能关注另一个 token（1），要么不能（0）
- 没有中间状态，信息流动控制粒度粗

**Gemma 3 的做法**：
- 注意力掩码为连续值（0 到 1 之间），每个 token 可以"部分关注"另一个 token
- 模型通过训练学习最优的注意力权重分配
- 提供更细粒度的信息流动控制，提升长序列建模能力

#### 特点4：SigLIP 视觉编码 —— 对比学习训练视觉能力

**Gemma 3 理解图片的方式**：
- 使用 **SigLIP** 方法训练视觉编码器
- 核心思想：将图片和对应的文字描述配对，通过对比学习让模型建立图文关联
- 视觉编码器与语言模型共享部分参数，融合更紧密

**与教学项目中模型的对比**：
- Kimi K3 用 **MoonViT**：独立视觉编码器 + 投影层把视觉信息转成语言模型能懂的格式
- Gemma 3 的视觉编码和语言模型**共享部分参数**，融合更紧密

### 2.3 训练优化亮点

#### 数据筛选：用 AI 筛选训练数据

**Gemma 3 的做法**：
- 收集海量候选数据（网页、书籍、图片等）
- 用 Gemini 评估每个样本的质量和教育价值
- 只保留高质量内容用于训练，提升数据效率

**效果**：
- 避免低质量数据干扰模型学习
- 通过筛选机制确保训练集质量，小模型也能获得良好效果

#### 训练后量化：让模型天生适应低精度

**Gemma 3 的特殊训练**：
- 训练后期模拟 INT8/INT4 低精度环境
- 模型学会在低精度条件下也能正常工作
- 训练好的模型可以直接部署到手机，无需额外转换

**与教学项目中模型的对比**：
- DeepSeek-V4/Kimi K3/Qwen3.6 用 **QAT（量化感知训练）**：全程用 FP8/FP4 训练
- Gemma 3 只在**最后阶段**模拟量化，实现简单但效果也不错

### 2.4 简单总结

| 维度 | Gemma 3 的特点 |
|------|---------------|
| 架构风格 | 极致效率，小参数大能力 |
| 长上下文 | 128K，用 Local-Global 降低计算量 |
| 多模态 | 全版本支持（1B 也能看图） |
| 注意力 | 软掩码，灵活控制信息流动 |
| 视觉编码 | SigLIP，与语言模型共享参数 |
| 定位 | 端侧部署、低资源环境、易用 |

## 三、两个模型的对比总结

### 3.1 Llama 4 vs Gemma 3

| 对比维度 | Llama 4 | Gemma 3 |
|----------|---------|---------|
| **规模追求** | 大（17B~2T） | 小（1B~27B） |
| **主要场景** | 服务器部署、多模态应用 | 端侧部署、手机/浏览器 |
| **长上下文** | 256K | 128K |
| **多模态** | 原生融合，共享骨干 | 全版本支持，轻量实现 |
| **MoE** | 是（16~128专家） | 否（Dense架构） |
| **注意力优化** | GQA（减少显存） | Local-Global（减少计算） |
| **训练特色** | 模型蒸馏（大→小） | 知识蒸馏（全程教学） |
| **量化** | 训练后 INT8/INT4 | 训练后模拟量化 |
| **开源协议** | Llama 4 License（有限制） | Gemma License（有限制） |

### 3.2 与教学项目中模型的对比

| 模型 | 架构类型 | 参数规模 | 上下文 | 长上下文方法 | 多模态 | 核心定位 |
|------|----------|----------|--------|-------------|--------|----------|
| **Llama 4** | MoE | 17B~2T | 256K | iRoPE（插值） | 原生融合 | 易部署的多模态 |
| **Gemma 3** | Dense | 1B~27B | 128K | Local-Global | 全版本支持 | 端侧高效 |
| **DeepSeek-V4** | MoE | 284B~1.6T | 1M | CSA+HCA（压缩） | 文本为主 | 超长上下文 |
| **Kimi K3** | MoE | 2.8T | 1M | KDA（差分） | 原生多模态 | 极致规模 |
| **GLM-5.2** | MoE | - | 1M | IndexShare（共享索引） | 有限 | 跨层优化 |
| **Qwen3.6** | MoE | 35B | 1M | YaRN（位置编码调整） | 原生多模态 | 中文优化 |

### 3.3 架构设计哲学差异

**美国模型（Llama/Gemma）**：
- 追求"够用就好"，不堆极致参数
- 注重部署便利性（端侧、低资源）
- 多模态设计更简洁

**中国模型（DeepSeek/Kimi/GLM/Qwen）**：
- 追求"越大越好"，参数竞赛激烈
- 注重长上下文能力（1M 是标配）
- 量化更激进（FP4/FP8 训练时就用）

## 四、对教学项目的补充价值

教学项目中的模型（DeepSeek-V4、Kimi K3、GLM-5.2、Qwen3.6）主要展示：
- **中国模型的技术路线**：大参数、长上下文、极致量化、MoE 普及

本文档补充的模型（Llama 4、Gemma 3）展示：
- **美国模型的技术路线**：效率优先、部署友好、架构简洁

### 关键互补知识点

| 教学项目已有 | 本文档补充 | 互补价值 |
|-------------|-----------|----------|
| 复杂的 MoE 架构（64~896 专家） | Gemma 3 的 Dense 架构（无 MoE） | 对比 MoE 是否必要 |
| 极致的长上下文（1M，动态压缩） | Llama 4 的 256K（简单插值） | 对比复杂度与效果的平衡 |
| 训练时量化（FP8/FP4） | Gemma 3 的训练后量化 | 对比量化时机选择 |
| 中期多模态融合（投影层） | Llama 4 的原生融合 | 对比融合时机 |

## 五、技术要点总结

**Llama 4**：
- 大模型变小：蒸馏（Behemoth→Maverick→Scout）
- 长文本：iRoPE（位置编码插值）
- 多模态：原生融合（视觉语言共享骨干）
- MoE：每个 token 激活 2 个专家（少而精）

**Gemma 3**：
- 小模型变强：全程教师指导（Gemini 参与训练）
- 长文本：Local-Global（局部注意力 + 全局聚合 token）
- 多模态：全版本支持（1B 也能看图）
- 注意力：软掩码（连续注意力权重，非二值）
