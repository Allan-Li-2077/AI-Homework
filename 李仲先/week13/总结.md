#第十三周作业：可加载 SKILL 的 Harness

## 一、作业目标

用 Python 实现一个简单的 harness，能够加载 SKILL 并在对话中使用。进一步将 harness 改造为**完整渐进式披露（Progressive Disclosure）**模式。

## 三、SKILL 格式

每个 SKILL 是一个目录，内含一个 `SKILL.md` 文件，由两部分组成：

1. **YAML frontmatter**：元数据，包含 `name`、`description`、`triggers`
2. **Markdown 正文（body）**：完整的工作流指令，告诉模型该怎么做

示例（`skills/code-review/SKILL.md`）：

```markdown
---
name: code-review
description: 当需要审查代码质量、查找 bug、提出改进建议或检查代码规范时使用此 skill。
triggers:
  - review
  - 审查
  - 代码质量
  - bug
---

# Code Review Skill

你是一位严谨的代码审查专家。请按以下流程工作：
1. 先通读目标文件，理解其职责与上下文
2. 逐项检查：正确性、可读性、安全性、性能、错误处理
3. 对每个问题给出：文件:行号、严重程度(高/中/低)、修复建议
4. 末尾给出总体评分(1-10)和三条最重要的改进点
```

harness 自带 frontmatter 解析器（`parse_frontmatter`），不依赖 `pyyaml`。

## 四、渐进式披露（Progressive Disclosure）

### 4.1 什么是渐进式披露

核心思想：**不要一开始就把所有信息塞进 prompt，而是分层次按需加载。**

| 层次 | 内容 | 何时加载 | token 开销 |
|------|------|---------|-----------|
| 第一层 | 每个 SKILL 的 `name + description`（目录） | 始终在 system prompt 中 | 小（每个 skill 约一行） |
| 第二层 | SKILL 的完整 `body`（工作流指令） | 模型调用 `load_skill()` 后才注入 | 按需，只加载相关的 |

### 4.2 为什么需要渐进式披露

- **省 token**：如果有 20 个 SKILL，每个 body 平均 300 字，全塞进 prompt 就是 6000 字。渐进式只放目录（20 行），模型选 1 个才加载那 300 字。
- **模型自主决策**：由 LLM 看着目录判断哪个 SKILL 相关，而非 harness 用关键词规则替它选——更灵活、更准确。
- **可扩展**：新增 SKILL 只需加目录 + `SKILL.md`，harness 自动发现并加入目录。

### 4.3 实现方式

用 **Function Calling 循环**实现渐进式披露：

```
用户提问
   │
   ▼
┌──────────────────────────────────────┐
│ 第一层：system prompt 包含 SKILL 目录  │
│ （只有 name + description）            │
└──────────────────────────────────────┘
   │
   ▼
模型看着目录判断：哪个 SKILL 相关？
   │
   ├── 相关 → 调用 load_skill(name) 工具
   │            │
   │            ▼
   │     harness 返回该 SKILL 的完整 body
   │     （第二层披露）
   │            │
   │            ▼
   │     模型按 body 指令生成回答
   │
   └── 不相关 → 直接回答，不加载任何 SKILL
```

对应代码：

- `build_catalog_system_prompt()` — 组装第一层（目录）
- `build_load_skill_tool()` — 定义 `load_skill` 工具的 function calling schema
- `execute_load_skill()` — 执行工具，返回完整 body（第二层）
- `run_progressive()` — function calling 主循环

## 五、关键代码说明

### 5.1 第一层：目录注入 system prompt

```python
def build_catalog_system_prompt(registry: SkillRegistry) -> str:
    catalog_lines = []
    for skill in registry.list_skills():
        catalog_lines.append(f"  - {skill.name}: {skill.description}")
    # 只放 name + description，不放 body
    return f"""你是一个智能助手。你可以使用以下 SKILL 来更好地回答问题。

## 可用 SKILL 目录
{chr(10).join(catalog_lines)}

## 使用规则
- 如果某个 SKILL 与用户问题相关，请调用 load_skill 工具加载它的完整指令
- 加载后，严格按照 SKILL 指令的流程工作
- 如果没有相关 SKILL，直接回答即可，不要强行加载"""
```

### 5.2 第二层：load_skill 工具

```python
def build_load_skill_tool(registry: SkillRegistry) -> list[dict]:
    skill_names = [s.name for s in registry.list_skills()]
    return [{
        "type": "function",
        "function": {
            "name": "load_skill",
            "description": "加载某个 SKILL 的完整指令。",
            "parameters": {
                "type": "object",
                "properties": {
                    "name": {
                        "type": "string",
                        "enum": skill_names,  # 只允许已加载的 SKILL 名
                    }
                },
                "required": ["name"],
            },
        },
    }]

def execute_load_skill(registry: SkillRegistry, name: str) -> str:
    skill = registry.get(name)
    if skill is None:
        return f"错误：未找到 SKILL '{name}'"
    return skill.body.strip()  # 返回完整 body
```

### 5.3 Function Calling 主循环

```python
def run_progressive(registry, user_query, model=None, max_steps=5):
    client, resolved_model = get_llm_client_and_model(model)
    if client is None:
        run_progressive_mock(registry, user_query)  # 无 Key 走 mock
        return

    messages = [
        {"role": "system", "content": build_catalog_system_prompt(registry)},
        {"role": "user", "content": user_query},
    ]
    tools = build_load_skill_tool(registry)

    for step in range(1, max_steps + 1):
        response = client.chat.completions.create(
            model=resolved_model, messages=messages,
            tools=tools, tool_choice="auto", temperature=0,
        )
        msg = response.choices[0].message
        reason = response.choices[0].finish_reason

        # 模型决定直接回答（未调用工具）
        if reason == "stop" or not msg.tool_calls:
            print(msg.content)
            return

        # 模型调用 load_skill → 返回 body → 下一轮模型按指令回答
        messages.append(msg)
        for tool_call in msg.tool_calls:
            skill_body = execute_load_skill(registry, tool_call.function.name)
            messages.append({
                "role": "tool", "tool_call_id": tool_call.id, "content": skill_body,
            })
```

## 六、Mock 模式

无 API Key 时，harness 自动走 mock 模式（`run_progressive_mock`），用规则匹配替代模型的 `load_skill` 决策，完整展示两层披露流程：

- 规则匹配用「触发词子串 + 字符级 Jaccard + 英文词级 Jaccard」，对中英文都稳健
- 也可用 `--mock` 强制走 mock

## 七、使用方式

```bash
# 列出所有已加载的 SKILL
python harness.py list

# 查看某个 SKILL 的完整内容
python harness.py show code-review

# 规则匹配（调试/mock 用）
python harness.py match "帮我审查一下代码"

# 渐进式披露执行（有 Key 调 LLM，无 Key 自动走 mock）
python harness.py run "帮我写单元测试"

# 强制 mock 模式
python harness.py run "帮我审查代码" --mock
```

## 八、与规则匹配版的对比

| 维度 | 规则匹配版（初版） | 渐进式披露版（最终版） |
|------|-------------------|----------------------|
| 选择方式 | harness 用关键词打分替模型选 | 模型看目录自主调用 `load_skill` |
| body 加载 | 一次性全部注入 | 按需加载，只注入被选中的 |
| prompt 开销 | 大（所有 body 都在） | 小（目录常驻，body 按需） |
| 灵活性 | 受限于关键词覆盖 | 模型理解语义，更准确 |
| 架构 | 单次调用 | Function Calling 循环 |

## 九、总结

本作业实现了一个可加载 SKILL 的 harness，核心是**渐进式披露**：

1. **SKILL 格式**：`SKILL.md` = YAML frontmatter（元数据）+ Markdown body（指令）
2. **两层披露**：第一层目录常驻 system prompt（省 token），第二层 body 按需通过 `load_skill` 工具加载
3. **模型驱动**：由 LLM 自主判断哪个 SKILL 相关并调用工具加载，而非 harness 规则匹配
4. **开箱即跑**：无 API Key 时自动走 mock，完整展示两层披露流程
