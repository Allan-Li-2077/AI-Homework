# Skill 优化报告：fetch-zzz-events

> 生成时间：2026-08-06

## 1. 优化概览

| 维度 | 原始方案 | 优化方案 | 改善幅度 |
|------|----------|----------|----------|
| 数据获取方式 | `webfetch` 获取完整HTML页面 | Python脚本调用SMW Ask API | 数据量减少 **63.3%** |
| 数据格式 | 443KB 非结构化HTML | 163KB 结构化JSON | 解析难度大幅降低 |
| LLM参与解析 | 是（需Task agent解析HTML） | 否（Python脚本自动解析） | **完全消除LLM解析开销** |
| 工具调用次数 | 4-5次（webfetch→Task→Read→Write） | 1次（bash运行脚本） | **减少75%+** |
| SKILL.md大小 | 1.4KB（45行） | 0.8KB（19行） | **精简43%** |

## 2. 核心优化点

### 2.1 数据源切换：HTML → SMW Ask API

**原始方案**：
- URL：`https://wiki.biligame.com/zzz/活动一览`（完整渲染HTML页面）
- 返回：443KB HTML，包含导航栏、脚本、样式等无关内容
- 问题：页面过大被截断（392KB+），LLM需二次读取解析

**优化方案**：
- URL：`api.php?action=ask&query=[[分类:活动]]|?名称|?开始描述|?结束描述|?开始时间|?结束时间|?类型|?所属版本|?TAG`
- 返回：163KB 纯JSON，仅含活动结构化数据
- 优势：字段语义明确，Python直接反序列化，无需正则或HTML解析

### 2.2 LLM解析 → Python脚本

**原始方案流程**（4-5次工具调用）：
```
webfetch(html) → 保存到临时文件(392KB+) → Task agent(Grep+Read解析)
  → 返回摘要给主agent → 生成HTML → Write写入文件
```

**优化方案流程**（1次工具调用）：
```
bash("python3 fetch_events.py") → 完成
```

**影响**：
- 消除了LLM阅读/理解392KB+ HTML的token消耗（估计节省 **~150K tokens**）
- 消除了Task子agent的额外token消耗
- 消除了多轮工具调用的固定开销（每次调用含系统提示+工具描述等）

### 2.3 Skill描述精简

| 项目 | 原始 | 优化 |
|------|------|------|
| SKILL.md行数 | 45行 | 19行 |
| SKILL.md大小 | ~1.4KB | ~0.8KB |
| 指令类型 | 详细步骤指导 | 一行命令+简要原理 |
| HTML样式规范 | 6条规则描述 | 内嵌在脚本中，无需描述 |

## 3. Token消耗估算

### 原始方案token消耗

| 步骤 | 估算token |
|------|-----------|
| webfetch返回的HTML内容（被LLM读取） | ~30,000（截断后的markdown摘要） |
| Task agent系统提示+工具描述 | ~5,000 |
| Task agent读取HTML文件+解析 | ~50,000 |
| Task agent返回结果 | ~2,000 |
| 主agent生成HTML | ~3,000 |
| 多次工具调用固定开销 | ~8,000 |
| **合计** | **~98,000** |

### 优化方案token消耗

| 步骤 | 估算token |
|------|-----------|
| bash调用脚本（命令+输出） | ~500 |
| skill指令读取 | ~800 |
| **合计** | **~1,300** |

### **总节省：约96,700 tokens（98.7%减少）**

## 4. 执行效率对比

| 指标 | 原始方案 | 优化方案 |
|------|----------|----------|
| 网络请求次数 | 1（webfetch） | 1（API，脚本内） |
| 工具调用次数 | 4-5次 | 1次 |
| 总执行时间 | ~15-30秒（含LLM推理） | ~2-3秒（脚本直接运行） |
| 失败风险 | 高（HTML截断、解析错误、格式变更） | 低（JSON结构化，字段明确） |
| 可维护性 | 低（HTML结构变更需修改prompt） | 高（API稳定，脚本独立） |

## 5. 文件结构

```
skills/fetch-zzz-events/
├── SKILL.md          # 精简的skill描述（19行）
└── fetch_events.py   # 自包含Python脚本（~5KB，无第三方依赖）
```

## 6. 结论

核心优化策略是**将LLM从数据解析环节中移除**，改用Python脚本直接处理结构化API数据。这带来三重收益：

1. **Token节省**：从~98K降至~1.3K（-98.7%），主要消除了LLM读取和解析大量HTML的开销
2. **速度提升**：从15-30秒降至2-3秒，消除了多轮工具调用和LLM推理延迟
3. **可靠性提升**：结构化JSON比HTML解析稳定得多，不受页面样式变更影响
