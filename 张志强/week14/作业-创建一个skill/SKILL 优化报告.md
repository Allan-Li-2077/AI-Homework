### 2.3 快速通道（新增机制）

```
优化前：所有项目一律执行 Phase 1-5 全量审计
优化后：先执行 3 步快速扫描 -> 低风险项目直接输出简版报告

快速扫描步骤：
1. Glob AndroidManifest.xml（已有前置探测）
2. Glob build.gradle + libs/*（已有前置探测）
3. 单次 Grep 提取关键信号（READ_PHONE_STATE/GET_TASKS/QUERY_ALL_PACKAGES 等）

预期覆盖：约 40-50% 的项目为低风险，可直接结束
```

## 五、关键优化点详解

### 5.1 快速通道（Fast Path）—— 最大收益点

**优化前问题**：
- 所有项目无论风险等级，一律执行 Phase 1-5 全量审计
- 对于一个简单的 Demo 应用或内部工具，也要完整走流程

**优化后方案**：
- 3 步快速扫描提取关键信号
- 无高风险权限/敏感行为 -> 直接输出简版报告
- 预估覆盖 40-50% 的低风险项目

### 5.2 Grep 合并 —— 工具调用减少 43%

**优化前问题**：
- Phase 2 搜 `initSdk|initSDK|...`
- Phase 4 又搜 `initSdk|initSDK|...`
- 同一批关键词重复搜索

**优化后方案**：
- 明确标注"复用 Phase 2 的 Grep 结果"
- 避免重复工具调用

### 5.3 条件执行 —— 避免无意义搜索

**优化前问题**：
- Phase 5 的 6 项检查（自启动、静默安装、应用列表等）固定执行
- 即使项目没有 `REQUEST_INSTALL_PACKAGES` 权限，也要搜索静默安装

**优化后方案**：
- 每项检查标注触发条件
- 仅当相关权限/信号存在时才执行

## 七、建议

1. **立即应用优化版本**：快速通道机制对低风险项目的收益显著
2. **持续监控**：收集实际执行数据，验证快速通道命中率
3. **迭代优化**：根据实际项目特征，调整"关键信号"列表
