## 2. Token Mixer（注意力机制）对比

七款模型在"如何做注意力"上可归为三类：**线性/递归注意力混合型**（Qwen、Kimi）、**稀疏注意力型**（DeepSeek、MiniMax、MiMo）、**纯全注意力型**（Hy3）。

### 2.1 Qwen3.6 / Qwen3.8：Gated DeltaNet + Gated Attention

两者共享同一套混合注意力设计（modeling_qwen3_5*.py 中实现一致），3/4 的层用线性注意力、每 4 层插入 1 个全注意力层：

- **Gated DeltaNet（线性层）**：QKV 先过 kernel=4 的因果 depthwise conv1d，然后走 chunked / recurrent gated delta rule（chunk 64）。递归更新带两个门：输入门 `g = -exp(A_log)·softplus(a + dt_bias)`、遗忘门 `β = sigmoid(b)`，Q/K 均做 L2 norm。每层维护 `[B, heads, k_dim, v_dim]` 的固定大小递归状态，长上下文不增加 KV。
- **Gated Attention（全注意力层）**：在标准 GQA 基础上，q_proj 额外输出一路 gate，注意力输出乘 `sigmoid(gate)`（config `attn_output_gate=true`），Q/K 做 RMSNorm。Qwen3.8 为 24 Q 头/4 KV 头、head_dim 256，RoPE 只作用于前 64 维（partial_rotary_factor=0.25）。
- 尺寸差异：3.8 是 64 层、hidden 5120、线性层 48 V 头/16 QK 头；3.6-35B-A3B 是 40 层、hidden 2048、32 V 头/16 QK 头、全注意力 16 Q 头/2 KV 头。

### 2.2 DeepSeek-V4：MLA + 滑窗 + 两级 KV 压缩

dsv4_model.py 的 Attention 是 DeepSeek 系 MLA 的延续，但外层套了稀疏检索：

- **MLA（多头潜变量注意力）**：Q 经 `wq_a → q_norm → wq_b` 低秩升维；KV 共享一个潜变量（`wkv → kv_norm`，单头、head_dim 512，RoPE 只加最后 64 维）；输出经分组低秩 `wo_a / wo_b`（o_groups=8/16）降维。KV 缓存只有一个 latent 头。
- **滑窗注意力**：每个 token 始终能看到最近 128 个 token（`get_window_topk_idxs`），另有一个可学习的每头 `attn_sink` 偏置。
- **CSA（压缩稀疏注意力，compress_ratio=4）**：`Compressor` 用可学习门控池化把连续 4 个 token 的 KV 压成 1 个块（ratio=4 时窗口有重叠）；`Indexer` 用一个小 Compressor + Hadamard 旋转 + FP4 量化，学习给每个 query 打分选出 top-k（Flash 512 / Pro 1024）个压缩块。
- **HCA（重度压缩注意力，compress_ratio=128）**：不学打分，按固定步长取压缩块（`get_compress_topk_idxs`），压缩比更高、更省。
- **层间配比**：Flash 为 `[0,0,4,128,4,128,...]`（0=纯滑窗层），Pro 为 `[128,128,4,128,...]`，即不同层看远处记忆的密度不同。

### 2.3 MiniMax-M3：MSA 块稀疏注意力

与 DeepSeek 的 Indexer 同源但作用在原始 KV 上：

- 前 3 层用稠密 GQA 注意力，其余 57 层用 **Lightning Indexer**（modeling_minimax_m3_vl.py 中 `MiniMaxM3VLIndexer`）：4 个索引头（=KV 头数）、head_dim 128，对每个 query 与全部 key 做小规模点积打分，按 128 个 key 一块做 max-pool，取 top-16 块 + 恒可见的 1 个本地块。
- 主注意力只对被选中的块做块稀疏注意力（`build_block_mask` 展开成稠密 mask，或走块稀疏 kernel），配套有专门的稀疏 cache 层（`MiniMaxM3VLSparseCacheLayer`，额外缓存 idx_key）。
- 代码注释明确写道"与 DeepSeek-V4 的 indexer 一样，这只是选择分支，不产生自己的残差输出（checkpoint 在稀疏层禁用了 index-value 路径）"。
- 与 DSV4 的区别：M3 索引的是**原始 key 块**（块内 max-pool 打分），DSV4 索引的是**先压缩过的 KV 块**；M3 不做递归/线性注意力。

### 2.4 MiMo-V2.5：SWA + GA 混排（无学习式索引）

最"朴素"的长上下文方案：

- `hybrid_layer_pattern` 中 0 的层（0、5、11、17、23、29、35、41，共 8 层）为全注意力 GA，其余 40 层为滑窗注意力 SWA（窗口 128）。（README 写 9/39，与 config 不符，以 config 为准。）
- SWA 层有独立的头配置：head_dim 192、v_head_dim 128、8 个 KV 头（GA 层为 4 个 KV 头，README 表格写反了）；`attention_value_scale=0.707` 对 V 做缩放。
- SWA 层带**可学习的 attention sink bias**（每头一个参数，`add_swa_attention_sink_bias=true`），保证窗口外也能"钉住"开头的 sink token。
- 部分 RoPE（partial_rotary_factor=0.334），GA 层用 theta=10M、SWA 层用 theta=10K，长程位置信息由 GA 层负责。

### 2.5 Hy3：纯 GQA 全注意力

没有任何长上下文技巧：64 头 GQA（8 KV 头、head_dim 128）+ per-head QK RMSNorm + 默认 RoPE（theta≈1115.9 万）。长上下文完全靠 256K 原生长度 + GQA 把 KV 缓存压 8 倍，属于"结构最保守"的一款。

### 2.6 Kimi-K3：KDA + Gated MLA

文本主干代码不在目录中，依据 config 与 README：

- 93 层中 69 层为 **Kimi Delta Attention（KDA）**、24 层为 **Gated MLA**（`full_attn_layers` 每 4 层一个，含最后一层），与 Qwen 的 3:1 混排思路一致。
- **Gated MLA**：MLA（q_lora_rank=1536、kv_lora_rank=512、qk_nope 128 + qk_rope 64、v_head 128、96 Q 头）加输出门，即"MLA 版 Gated Attention"。
- **KDA**：线性注意力（delta rule 家族），配置里有 short conv kernel=4、`gate_lower_bound=-5`、`use_full_rank_gate`、96 头 head_dim 128，与 Gated DeltaNet 类似但有自身细节（如门下限约束）。
- **Attention Residuals（AttnRes）**：config `attn_res_block_size=12`，说明每 12 层一个注意力残差块（块内注意力输出以额外路径向后传递），这是 Kimi 独有的"跨层注意力残差"结构。

## 3. FFN / MoE 对比

### 3.1 激活函数

- 绝大多数用 SwiGLU（silu·up）：Qwen、DSV4、Hy3、MiMo。
- Kimi-K3 用 **SiTU-GLU**（config `hidden_act=situ`，含 `activation_situ_beta=4.0` / `linear_beta=25.0`）。
- MiniMax-M3 用 **swigluoai**：`gate·sigmoid(α·gate)`（α=1.702），gate 与 up 都做 ±7 截断（swiglu_limit），DSV4 的专家层也有类似截断（limit=10）。

### 3.2 路由与专家组织

| 模型 | 专家数/top-k/共享 | 打分函数 | 选择 bias | 归一化/缩放 | 辅助损失 | 其他 |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3.6 | 256 / 8 / 1（sigmoid 门控共享） | softmax | 无 | 归一化后无额外缩放 | 有（Switch 式 load-balancing loss） | 专家权重存为 3D 张量，gate_up 融合 |
| DSV4 | 256/384 / 6 / 1（无门控） | sqrtsoftplus | 有（只影响 topk 选择） | 归一化 × routed_scaling_factor | 无（noaux_tc） | 前 3 层 hash 路由（token→expert 查表）；专家 FP4 |
| Hy3 | 192 / 8 / 1（无门控） | sigmoid | 有（e_score_correction_bias） | 归一化 × 2.826 | 无 | 首层稠密；shared inter = moe_inter × 共享数 |
| Kimi-K3 | 896 / 16 / 2 | sigmoid | 有（use_routing_bias） | latent_moe_use_norm | 无（noaux_tc） | **LatentMoE**：路由在 3584 维潜空间做（routed_expert_hidden_size），再映射到专家 |
| MiMo-V2.5 | 256 / 8 / 0 | sigmoid | 有（e_score_correction_bias） | 归一化 × 1.0 | 无（noaux_tc） | **无共享专家**；首层稠密；noaux_tc 仅推理实现 |
| MiniMax-M3 | 128 / 4 / 1（无门控） | sigmoid | 有（e_score_correction_bias） | 归一化 × 2.0 | 无 | 前 3 层稠密；shared_inter 3072 独立于专家 |

### 3.3 关键差异点

- **唯一有 MoE 辅助均衡损失的只有 Qwen3.6**（`load_balancing_loss_func`），其余全部走 noaux_tc（无辅助损失 + 选择 bias 的流派）。
- **Kimi 的 LatentMoE** 最特殊：router 打分不在 hidden 维直接做，而是先在 3584 维潜空间选专家再计算，配合 896 个专家 top-16，稀疏度最高（约 1.8% 激活率）。
- **MiMo 没有共享专家**，是唯一的"纯 top-k"设计。
- **共享专家门控**：只有 Qwen 给共享专家输出乘 sigmoid 门，其余模型直接相加。

## 4. 归一化、残差与信息通路

### 4.1 归一化

- 全部使用 RMSNorm；Qwen、MiMo、Hy3 为常见 RMSNorm。
- MiniMax-M3 用 **Gemma 风格 RMSNorm**（权重初始化为 0，输出乘 `1+weight`，fp32 归一化）。
- Kimi 的 SiTU 激活前有专门配置（situ beta），与各家激活归一化思路不同。
- Qwen/M3/DSV4 对注意力 Q/K 做 RMSNorm（per-head），Hy3 也做 q/k norm，MiMo 未做 q/k norm。

### 4.2 残差结构

- **标准 Pre-Norm 残差**：Qwen、Hy3、MiMo、M3（input_layernorm → mixer → 残差；post_attention_layernorm → FFN → 残差）。
- **DeepSeek-V4 独有 Hyper-Connections（mHC）**：hidden state 在网络内保持 hc_mult=4 份副本；每层用可学习矩阵 `hc_attn_fn/hc_ffn_fn` 计算混合系数，经 **Sinkhorn（20 轮）** 分解成 pre/post/comb，`hc_pre` 把 4 份合成 1 份喂注意力/MoE，`hc_post` 再展开回 4 份，最后在输出端用 `hc_head` 合并。这不是普通残差，而是"多副本流形约束连接"。
- **Kimi 的 AttnRes**：在常规残差之外，每 12 层额外做跨层注意力残差（Attention Residuals），属于块级残差。

| 模型 | 策略 | 效果 |

## 7. 多 Token 预测（MTP）

- **DeepSeek-V4**：代码中实现了 1 个 `MTPBlock`（e_proj/h_proj 融合嵌入与隐藏状态，共享 embedding/lm_head，`num_nextn_predict_layers=1`）。
- **Qwen / Hy3 / MiMo / M3 / Kimi**：config 或 README 有 MTP 字段（Qwen mtp_num_hidden_layers=1、Hy3 nextn=1、MiMo 3 层 329M、M3 num_mtp_modules=7、Kimi vLLM 支持 next_mtp），但**目录内 HF 代码全部忽略 mtp 权重**（`_keys_to_ignore_on_load_unexpected`），即本仓库代码未实现 MTP。
- 结论：MTP 已是大模型标配趋势，但除 DSV4 外其余六家的 HF 参考实现都没有落地。

## 8. 量化与精度

| 模型 | 方案 |
| --- | --- |
| Qwen / Hy3 / M3 | BF16（M3 config torch_dtype=bf16，无量化配置） |
| DSV4 | FP8 主体（动态逐块量化，block 128×128，ue8m0 缩放）+ 专家 FP4；Indexer 加 Hadamard 旋转再量化，对齐 QAT |
| MiMo-V2.5 | FP8 动态逐块量化（e4m3），o_proj 层豁免 |
| Kimi-K3 | MXFP4 权重 / MXFP8 激活，SFT 阶段起量化感知训练（QAT） |

## 9. 相同点归纳

1. 全部是 decoder-only 因果语言模型，输入层为 token embedding，输出为未 tie 的 lm_head。
2. 全部用 RMSNorm 族归一化、RoPE 族位置编码、GLU 族 FFN（SwiGLU/SiTU-GLU/swigluoai），无 ALiBi、无绝对位置嵌入（视觉塔除外）。
3. 大规模模型全部走 MoE + 共享专家路线（除 MiMo 无共享专家），且大多用 sigmoid/带 bias 的 noaux 路由。
4. 全部面向长上下文（256K~1M），并都在"注意力成本"上做文章：线性注意力（Qwen/Kimi）、稀疏/压缩注意力（DSV4/M3/MiMo）、或 KV 压缩（GQA/MLA）。
5. 多模态成为主流：除 DSV4、Hy3 外都带视觉塔；MiMo 还带音频。
6. 混合注意力（线性/全注意力 3:1、SWA/GA 混排、压缩/索引混排）成为大模型新范式，纯全注意力的只剩 Hy3。

## 10. 一句话总结

- **Qwen3.6/3.8**：Gated DeltaNet 递归线性注意力 + Gated Attention 混排，3.6 换 MoE、3.8 保持稠密，是同族最稳的"混合注意力"实现。
- **DeepSeek-V4**：MLA + 滑窗 + 学习式压缩稀疏注意力（CSA/HCA）+ Hyper-Connections，工程最重的长上下文方案。
- **Hy3**：结构最传统的 GQA + 大 MoE，靠规模与训练取胜。
- **Kimi-K3**：KDA 线性注意力 + Gated MLA + AttnRes + LatentMoE，把 Qwen 式混合注意力和 MoE 稀疏度推到极致（896 专家 top-16）。
- **MiMo-V2.5**：SWA/GA 混排 + sink bias 的"轻量"长上下文路线，还做了原生音频。
- **MiniMax-M3**：GQA + 块稀疏 MSA（Lightning Indexer 选块），与 DeepSeek-V4 的 Indexer 同源但索引原始 KV 块，并带 7 模块 MTP 配置。
