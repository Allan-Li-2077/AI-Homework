# 并行 Subagent 对比实验报告

## 实验目标

验证“主 Agent 下发多个 Subagent 并行完成多项工作”相比串行执行是否能减少整体耗时。

## 测试任务

```text
1. 模拟分析2026-27赛季76人主场对湖人的核心球员对位和胜负预测
2. 基于2026年总决赛后的最新阵容，比较76人恩比德、马克西、杰伦布朗、詹姆斯与湖人东契奇、里夫斯、凯斯勒等阵容的内线、锋线和后场匹配
```

## 实验方法

同一个问题运行两次：

- 并行模式：使用 `ThreadPoolExecutor` 同时运行多个 Subagent。
- 串行模式：使用 `for` 循环依次运行相同 Subagent。

主流程、搜索工具和汇总逻辑保持一致，只改变 Subagent 执行方式。

## 实验结果

| 指标 | 并行 ThreadPool | 串行 for 循环 |
|------|----------------:|--------------:|
| 测试题数量 | 2 | 2 |
| 平均墙钟时间 | 45.65s | 85.28s |
| 总流程加速比 | 1.87x | - |
| Subagent 阶段平均加速比 | 4.60x | - |

## 结果分析

并行版本平均总耗时为 45.65 秒，串行版本平均总耗时为 85.28 秒，总流程加速约为：

```text
85.28 / 45.65 = 1.87x
```

Subagent 阶段平均加速达到 4.60x，说明多个相互独立的分析任务适合并行执行。

总流程加速比低于 Subagent 阶段加速比，原因是主 Agent 的任务拆分、结果汇总和最终报告生成仍然是串行步骤。这符合 Amdahl 定律：整体加速效果会受到不可并行部分的限制。

## 结论

本实验说明，在 NBA 赛前模拟分析这类多维度任务中，主 Agent 将阵容核验、球员对位、战术匹配和胜负预测拆分给多个 Subagent 并行执行，可以显著减少等待时间。

该结果支持本项目的核心设计：复杂任务由主 Agent 编排，多个 Subagent 并行处理独立子任务，最后由主 Agent 汇总生成完整报告。
